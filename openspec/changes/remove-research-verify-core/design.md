# Design

## Context

已有独立 core 安装 smoke，但默认发行包、部署入口和前端仍包含 Research；通用测试也复用了研究夹具。仅隐藏菜单不能证明底座独立。

## Goals / Non-Goals

目标：从打包、import、注册、seed、页面和测试依赖中移除旧应用；用空库验证正常身份与资源工作流。非目标：新应用、新设计、外部身份生产部署、清空旧数据或重写通用执行机制。

## Decisions

1. 删除 tracked 应用源码；Git 历史与验收存档保留。默认应用注册为空，成员自建/发布材料和通用账户资源保留。旧应用未安装不触发旧数据删除。
2. 使用独立命名的新 PG 服务/数据库及新工作目录，严禁复用盘点中的旧卷和 SQLite；只使用明确合成账号、密码和测试资源，不接触 OPENCODE_GO。
3. 由实际归属决定删除测试：仅验证已删除应用行为的测试随应用移除；通用身份、资源、预算、取消、历史与远程契约测试迁移到显式合成 test application/工具，不能靠 import skip 或减弱断言追绿。
4. 前端保持现有设计；主导航仅通用应用/任务/资源/管理。处理空应用/空任务状态、登录/退出/重登、有效直接 URL/刷新及旧研究 URL，不建立新科研入口。
5. 生产模式浏览器使用本地合成身份的真实认证协议；如真实外部身份未提供，则明确未验收，不把 demo 路径外推成生产身份兼容。
6. 重型测试、PG 与浏览器串行；worker 仅运行静态或明确便携检查。root 对跨边界源码、证据和最终 Draft/精确 CI 负责。

## Risks / Trade-offs

旧 Research 的未完成任务在不安装该应用时不能继续；本次不运行新代码对旧数据库做回收。独立性测试只证明新空库和显式合成通用应用；真实账号/外部服务、历史迁移及原偶发超时的根因不因本次通过而关闭。

## Migration Plan

不执行 destructive migration，不自动删旧 catalog/records。代码移除保留在单独 Draft；需要恢复旧应用时可检出此前 main。旧数据永久清空由准确目标清单和即时确认单独控制。
