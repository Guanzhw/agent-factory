# Spec Delta

## Purpose

成员能够发布固定目标的 CLI/MCP 操作并在同一材料版本下选择独立个人账号或明确共享账号。公开操作不携带私有凭据，执行与恢复持续绑定原始操作、账号和调用身份，避免跨账号替换及重复外部效果。

## ADDED Requirements

### Requirement: 显式公开不可变操作
系统 SHALL 允许成员显式创建公开操作版本，其身份包含完整执行配方、输入 schema、权限与执行限额；不得自动将已有私有资源转为公开材料。发布内容不得包含凭据值或凭据引用。

#### Scenario: 修改配方必须形成不同身份
- **WHEN** 成员修改 MCP URL/remoteToolName 或 CLI executable、固定参数、参数映射、stdin、cwd、非秘密环境变量、凭据注入变量名、输出格式之一
- **THEN** 新定义具有不同操作 hash，旧材料版本与既有任务保持不变；只有 descriptor 相同不足以兼容

#### Scenario: 私有配置不自动公开
- **WHEN** 成员已有包含私有参数的资源并进入创建公开操作页面
- **THEN** 系统不复制并发布该配置；成员明确提交可公开配方，凭据仍仅由账号资源选择

### Requirement: 同一操作支持独立账号
系统 SHALL 允许多个成员及同一成员的多个账号引用同一操作版本执行同一材料 id/version/hash。账号必须满足该操作的精确目标、协议与凭据作用域，提交后不得换用等价账号或修改配方。

#### Scenario: 两用户选择各自账号
- **WHEN** Alice 与 Bob 使用同一发布材料分别选择个人账号，Bob 再选择第二个个人账号
- **THEN** CLI/MCP 外部观察分别对应选中账号，任务 actor 不变，未重新发布材料，原账号绑定保留

#### Scenario: 精确不匹配拒绝
- **WHEN** 账号引用不同操作版本、schema、目标或 hash
- **THEN** 提交或调用在业务 dispatch 前明确失败，不以相同工具名放行

### Requirement: 撤销与共享按原作用域生效
系统 SHALL 在每次调用前重新校验成员、原材料可用性、所选账号及其共享/凭据状态。撤销一个账号不得撤销其他账号或公共操作；撤销材料不得被缓存操作绕过。

#### Scenario: 共享账号与独立账号撤销隔离
- **WHEN** Bob 明确选择 Alice 共享账号执行一步，随后 Alice 撤销该账号或共享
- **THEN** 该原连接的下一步失败且无业务调用；Bob 自有账号仍能在有效材料的新任务中使用，原任务不自动切换账号

#### Scenario: 原材料或 actor 失效
- **WHEN** 两步之间材料被撤销、actor 被禁用或原凭据被撤销
- **THEN** 下一步无业务调用，恢复过程不得绕过同一即时检查

### Requirement: 原生执行与恢复保留身份
系统 SHALL 在原生执行、支持的 child 路径和重启后保留原材料、操作版本、账号绑定及原调用身份。完成效果不得重派发；无法确认的效果维持 UNKNOWN，不以换账号、换操作或新 call id 重试。

#### Scenario: 双账号重启后继续原任务
- **WHEN** 第一阶段已完成并重启服务，再恢复两个账号的后续步骤及支持的 child
- **THEN** 原选择与外部身份保持一致，已完成调用计数不增加

#### Scenario: 外部已执行但确认丢失
- **WHEN** CLI/MCP 已产生效果但确认丢失，随后重启并读取或恢复任务
- **THEN** 原效果保持 UNKNOWN 或依据原操作证据核对，业务计数不因恢复增加

### Requirement: 兼容与凭据隔离
系统 SHALL 保持旧 installed adapter、旧 member resource、plan 和 effect 的身份及恢复语义。公开材料、共享账号投影、模型输入、错误与日志不得泄露凭据值；共享账号不得暴露凭据 ref/revision。

#### Scenario: 旧数据和公开投影
- **WHEN** 升级后恢复旧任务并读取新公开操作及共享账号
- **THEN** 旧任务使用原绑定，新投影仅展示公开配方与允许的来源信息，合成凭据及共享凭据引用不出现
