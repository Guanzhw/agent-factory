# Spec Delta

## Purpose

让研究会话中的成员及其 Agent 在目标、共享权限、预算和停止边界内向同事助手提问并采用可核权证据；中断、重复操作及权限变化都保留原问题身份，不隐式分享私有上下文或重复执行。首片实现人工 UI 路径，紧接续片实现获准自主路径；人工选择不构成后者的逐条审批门禁。

## ADDED Requirements

### Requirement: 人工路径发送明确确认的问题

首片人工 UI 路径 SHALL 允许成员 A 从自己的研究会话选择成员 B 的助手并确认问题文本，持久绑定原会话、原请求、接收助手和文本；只发送该文本及必要的原消息身份，不自动附带私有目标、历史、文件、记忆或凭据。Agent 自主路径紧接续片实现，MUST NOT 把人工确认作为其全局逐条审批要求。

#### Scenario: 正常提问及私有边界
- **WHEN** A 从自己的会话确认向 B 发送问题
- **THEN** 原会话已发列表和 B 的收到列表能找到同一原问题；B 只能看到确认文本和必要身份，不能读取 A 的会话私有内容

#### Scenario: 跨用户或原请求改绑
- **WHEN** B 尝试从 A 的会话发问，或 A 以同 requestId 更改会话、助手、文本，或将独立问答的旧请求绑入会话
- **THEN** 系统拒绝，不创建消息、预算或任务，也不泄露不属于操作者的会话内容

### Requirement: 原问题可找回且重复请求只读

系统 SHALL 使消息及原会话关联一同提交或一同回滚；丢失响应、退出后重启、刷新及相同请求重试均能核对原问题，不改原 endpoint、预算或任务。已有原记录的重复发送 MUST NOT 自动接续执行；查询未找到记录也 MUST NOT 自动重新发送或换新请求标识。

#### Scenario: 提交后启动前退出
- **WHEN** 消息与会话关联已提交，但服务在首次启动前退出
- **THEN** 重启后 A 按原会话/requestId、B 按收到列表都能找回原问题；显示尚未准入，A 重试和读取不启动任务

#### Scenario: 并发重复及绑定失败
- **WHEN** 同一请求并发到达，或持久关联过程中发生确定失败
- **THEN** 成功路径仅保留一个原问题和一次预算绑定；失败事务不遗留已提交消息、预算或不可找回的关联

#### Scenario: 网络失败且原请求尚未找到
- **WHEN** 发送结果未确认，成员主动查询得到本会话原 requestId 尚未找到
- **THEN** 保留原 requestId、助手和发送文本，允许成员明确点击按原请求再次发送；仍不存在时才首次创建，迟到或已存在的相同请求只读原记录，不自动恢复原任务；其他读取错误不冒充未找到

### Requirement: 仅沿原授权执行和接续

系统 SHALL 仅在 B 既有有效 QA endpoint 与预算授权下执行首次新问题；浏览器离线不影响已接受任务。首片人工路径的无任务消息由 B 明确接续并核验原绑定；这不限制续片既有授权内的可信自动投递。已有 task 无论状态或 runId 是否明确均只核对，不重新提交；读取错误或任意 404 MUST NOT 构成恢复许可。

#### Scenario: B 离线及明确接续
- **WHEN** B 浏览器离线但 QA 配置有效，A 首次提交问题；或 B 随后明确接续一个已提交无任务的原问题
- **THEN** 任务使用 B 的原配置、原预算、原问题文本执行；并发接续仍最多提交一次，A 无权调用 B 的接续动作

#### Scenario: 未知结果及旧 endpoint 禁用
- **WHEN** 原生接受后 ACK 丢失，或任务 reservation 后进程退出，或无任务消息对应的旧 endpoint 已禁用
- **THEN** 已有任务保留原 ID 且不重发；无任务的禁用 endpoint 消息拒绝新启动，不换新配置或新预算；明确显示可核对状态而非伪报成功

#### Scenario: 接收方不可用
- **WHEN** B 尚未配置 QA 或预算已耗尽
- **THEN** A 得到具体不可用原因并保留草稿，B 可从自己的入口打开既有配置；不能由 A 代配，消息持久化不能替代执行授权

### Requirement: 回答与证据读取时重新核权

系统 SHALL 在原会话展示绑定原问题的回答和来源，读取时重新核验双方成员及来源权限；来源不可用时隐藏不可再授权的回答正文和来源内容，保留可见的原问题状态。回答存在 MUST NOT 被当作任务整体完成或研究结论已验证。

#### Scenario: 收到回答或证据不足
- **WHEN** B 的 QA 记录原问题回答
- **THEN** A 返回原会话可看到回答及可读来源，任务状态单独展示；没有可用来源时明确证据不足，不生成虚构引用；首片人工 UI 路径仅收到回复不启动 A 的助手

#### Scenario: 来源撤回或成员失效
- **WHEN** 回答后来源撤回、共享权限改变或任一参与者权限失效
- **THEN** 后续读取和采用均重新核验，包括 A 会话详情/卡片中的已采用副本；隐藏失授权正文/来源但保留可见的原问题 ID/状态，不删原记录；第三人不能靠 ID 或列表读取私有问题

### Requirement: 人工路径选择下一轮采用回复

首片人工 UI 路径 SHALL 在 A 选择一条本会话原问题的可用回复并提交下一轮时才将其作为引用证据纳入上下文，保留原文、来源和任务身份并核对原请求与容量。此操作不限制获准自主路径。两条路径已采用回复在后续读取/主请求/摘要前仍须核权；超限或授权失效 MUST 拒绝相关准入，旧摘要或已保存请求不得绕过。

#### Scenario: 选择与执行分开
- **WHEN** 在首片人工 UI 路径中，回复到达、A 仅打开或选中回复但尚未提交下一轮
- **THEN** 不注入当前运行或纠正队列、不启动模型；提交后仅按本次明确选择及下一轮原请求纳入，重复提交不创建第二轮

#### Scenario: 采用边界与迟到摘要
- **WHEN** A 选择别人的/其他会话的原问题、原问题尚无可用回复、实际投影超限，或摘要期间已采用来源撤回
- **THEN** 系统就地说明不可采用原因；不调用后续主模型、不丢弃既有约束或将迟到摘要变成可用证据

### Requirement: 可操作入口与任务所有权保持一致

系统 SHALL 在桌面和手机提供原会话提问/已发问题、B 收到的问题、原问题/来源及明确采用入口；保持返回上下文、加载/空态/错误、刷新与重复点击语义。停止执行继续受原任务 owner 和原请求边界约束，A 停止自己的研究 MUST NOT 获得停止 B 任务的权限。

#### Scenario: 双方连续使用
- **WHEN** A 提问后离开并返回，B 从收到的问题打开原消息，再查看自己的原任务
- **THEN** 双方知道用途、下一步和当前结果；后退/前进/刷新不丢原消息归属、不重复发问；移动端错误贴近字段，未发送文本离开有明确提示

#### Scenario: 停止与历史兼容
- **WHEN** A 停止自己的研究，或尝试控制 B 的任务，或读取本片前的独立问答
- **THEN** 仅 A 自己的任务按原停止契约处理，越权控制被拒绝；旧问答、历史任务和原结果仍可查，不自动迁入会话或重放

### Requirement: 紧接续片提供获准自主异步路径

紧接续片的自主路径 SHALL 让 Agent 在现有目标、共享权限、预算和停止边界内主动询问，并自动关联、通知和采用可核权的返回证据，无逐条人工确认。它 MUST 复用已有消息/投递与原生执行准入，不新建第二总线；超权限、修改他人资源及 UNKNOWN 副作用保持阻止或原操作核对。首片未实现此接线，不能标为完成。

#### Scenario: 获准自主问答与离线返回
- **WHEN** 续片中 Agent 在既定范围发问，B 浏览器离线，原问题随后收到可核权证据
- **THEN** 无逐条人工审批，问题/回复自动关联原会话，在获准安全点采用并可见；重复或乱序通知不得重复采用或启动任务

#### Scenario: 自主路径停止和恢复边界
- **WHEN** 续片中预算耗尽、研究已停止、来源撤回，或服务重启时原操作结果 UNKNOWN
- **THEN** 迟到回复可保留但不擅自唤醒已停止研究，不新开越权/超预算执行，不泄露私有资料，不重放未知任务；核对原身份并明确当前状态
