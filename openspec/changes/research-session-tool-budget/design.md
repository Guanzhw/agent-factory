# Design

## Context

基线 `05233580b04f290c40d463a7240d05cb213f45ac`。动机见 proposal。上一真实任务 27 次 DeepSeek 请求（含 1 次摘要）、4 用户轮、31 个工具提议/26 个执行/5 个额度拒绝；只有首修复到续修明确由 8 上限迫使，观察轮和最后重验本是 QA 安排。续轮重复读取同哈希内容 54,079 字符，不能全算无用。前三轮墙钟 180.079 秒；不是下一次单轮耗时保证。

`config.py:28` 已有上限 8，`runtime.py:103` 已给共享 Agent 使用它；`session_setup.py:74` 新会话默认又固定 8。现有 Plan schema 允许 1–128，`delegation.py:252` 在执行前核持久共享额度。Agno 3.1.0 安装源码已与官方固定版本核一致；无需升级。

## Goals / Non-Goals

**Goals:** 用正常配置打通一次完整代码目标，明确旧低预算下的真实停止行为。

**Non-Goals:** 不改模型分派四响应方法、共享 Agent 属性或推理循环；不新增预算余额、自动续轮、流式兼容层或应用角色。网络获取、真实 GPU、目标硬件容量和未完成全站易用性工作仍属后续事项。输出额度不等于费用上限；不自动重绑旧研究会话。

## Decisions

1. **工具额度接两个配置点。** `Settings.from_env` 接 `FACTORY_MAX_TOOL_CALLS`，Settings 入口按现有 1–128 验证；Research 新会话默认取部署 cap。未配置仍为 8，不改所有模板默认或旧 Plan。原 Agent 已使用 settings，不改 `runtime.py`。
2. **候选 32，保留现有时间配置。** 本样本主流程已执行 24 工具且必要编辑/复核曾被拒，先用 32 做真实单目标验收。60 秒操作与 300 秒运行已有本样本证据，先不提高；候选额度不是成功保证或费用保证。
3. **持久额度继续权威。** 不采用初步 Go 审查讨论的逐 Plan Model 参数覆盖：没有实际失败要求这层改动。native cap 提高后，旧/自选 Plan 8 的第 9 次由 durable pre-hook 拒绝，记录 `protected_denied`，经 `StopAgentRun`/protected-failure 收尾；验明 stopped、DONE 结果与可显式继续。现有泛“本轮失败”提示是体验限制，本片不为它增加新状态层。部署降低 cap 也仍会影响 native 执行；不作旧执行行为零变化承诺。
4. **完整任务验收。** 复用已核公开 pytest-asyncio 缺陷任务，只给一次完整目标，不强制观察先停。测试应在助手结束后独立只读核结果，不把 QA 重验算用户必须多轮。记录真实失败和调用数，不预喂参考修复、不以脚本模型冒充自主完成。实模成功不以超过 8 次为条件，不为验收拆调用凑次数；未实际超过时如实标分支未覆盖，第 9 次能力由原生 PG 独立验证。
5. **按实测补齐模型输出配置。** `219a22f` 单目标请求 9 次均 HTTP 200，同轮 17 工具完成，但最后 `finish_reason=length`、输出 4096（reasoning 3794），源码尚未修改。`byok_model._body` 与 `owner_runtime_broker._completion` 固定 4096 是产品限制；保持 `decode_response` 拒绝不完整响应。给个人模型 JSON 增加可选正整数 `maxOutputTokens`，正常 UI 可配置，新实测候选 16384，不宣称充分。缺省仅在请求构造读 4096，不回填旧记录、命令 fingerprint 或历史 scope。两请求路径共用现有模型配置读取逻辑，CC 发 `max_tokens`，Responses 发 `max_output_tokens`；不接受模型/远端客户端覆盖 owner 配置，不新增 provider 上限表或全局部署参数。
6. **复用保存与授权，不写新账本。** 已有 JSON revision、凭据引用、绑定和原请求恢复承载此字段；前端 pending、回执匹配、设默认、轮换/重绑密钥都保留它。调整输出额度使用已有 configure 阶段及现有凭据引用，不调用凭据写入/轮换接口。共享使用者只能读取；所有者更新按原规则生成新 revision。`billing_mode.ledger_for_plan` 对 owner BYOK 明确返回 None，因此不修改 `PricingRevision`、计费 reserve 或托管模型默认。修改配置后旧研究会话仍绑定原版本，可能需核对；本片只验配置后新会话，不添加自动迁移或重放。

## Risks / Trade-offs

- [部署 ceiling 是全局配置] → 其他应用显式预算不被改写，但高预算任务的 native 可执行次数可能改变；测试旧/自选低额度仍零越限副作用。
- [旧低预算收尾可能没有正常模型总结] → 验明拒绝事件、终态、已完成结果与显式继续；不假称同旧收尾，也不扩大为通用额度框架。
- [32 或时限仍可能不足] → 记录实测再决定，不为得到通过预加限制层或收费 fallback。
- [模型提供方不接受所填输出额度] → 展示现有真实错误，不静默降额、改模型或反复调用；截断内容不能成为工具副作用。
- [额度更新影响旧连接] → 沿用配置 revision 行为并在 UI 说明；不声称旧会话自动改绑或恢复。

## Migration Plan

无 schema 迁移，不回写会话/Plan。部署方显式设置候选额度，回退配置只影响后续原生执行与新默认，不删除数据或重放任务。实现前独立评审；实现后准确 head 测试、完整累计 diff 复审与 full CI，发布按既有专项许可处理。
