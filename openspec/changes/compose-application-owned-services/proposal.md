# Proposal

## Why

同一服务器需要同时安装科研与第二应用，保证任务投影、取消及关闭各有明确拥有者。现有单回调和整类替换可能发生覆盖，尚未通过双应用运行复现；#98 已提供统一有界关闭基础。

## What Changes

- 第一阶段组合真正被多个应用使用的任务投影、控制、运行证据及生命周期入口，按原持久化身份派发，重复归属在启动时报错。
- 第二阶段由科研应用实例直接持有并传递 service graph，迁移全部消费者后删除进程级 `id(store)` 关联。
- 保持 Agno 原生执行、UNKNOWN 原身份、未确认资源占用及单整体 35 秒关闭期限；不按应用重新计时。
- 用最小惰性第二应用验证同服务器共存、交换安装顺序和双服务器隔离，不新增业务应用或通用依赖注入框架。

## Capabilities

### New Capabilities

- `application-service-composition`：静态多应用装配、原操作精确派发与实例依赖生命周期隔离。

### Modified Capabilities

无；当前主规格目录尚无已发布能力规格。本变更保留 #98 的关闭行为。

## Impact

基线：`ab5a98e`（#98 `5799403` 加 #99 规划）。实现尚未开始。涉及 core 接入点、科研装配与 graph 消费者、deployment 显式组合及合成/真实 PostgreSQL 验收。#97 控制/读取修复尚待提交后集成，不依赖其工作区未提交接口。保留现有 HTTP 行为与原操作身份，不新增依赖或数据库迁移作为默认方案。
