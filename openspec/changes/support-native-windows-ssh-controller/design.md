## Lease and credential ownership
`SSHAgents.acquire` selects its existing Linux implementation or a narrow Windows lease implementation. Do not add a public platform abstraction/registry. Windows lease has the existing public key and `validate()` contract, an expiry and a private callback for fresh credential resolution. No persistent socket, global agent or stored passphrase. Acquisition validates the existing owner/binding guard and vault authorization before resolving/decoding the key; only public identity and a scoped resolver survive acquisition, not decoded secret bytes.

Every spawn validates the same guard and lease expiry again, reserves one Windows carrier slot, resolves the exact vault reference/revision/provider/destination again and checks its public identity against the lease. A fresh invocation password encrypts that invocation's key only. Immediately before the one pipe release, recheck authorization/expiry through the original callback. The existing `before_write` guard continues before helper protocol effects and the existing post-exchange lease validation remains. No database callback under the carrier accounting lock. Revocation must deny fresh use; an already started operation still follows existing cancellation/UNKNOWN recovery rules, not a fabricated success.

Windows `max_agents` bounds concurrent live credential carriers (each call needs its own job/password); unlike Linux's reused agent process, Windows does not cache credentials. This is a deliberately stricter local resource bound, not an unbounded per-lease process fanout. The existing configured lease TTL is an absolute upper bound, never renewed by use. Both consumers pass their one absolute monotonic deadline explicitly to pinned_ssh; the Windows scope and the existing exchange share min(caller deadline, lease expiry), rather than starting independent timeout windows. Release the slot on every failed construction, exit, cancellation and close. Slot reservation, the closed flag and registration of an initializing carrier occur under the same accounting lock. The pending record exists before resolving credentials or creating a process. Service close atomically marks closed/cancelled and then performs cleanup and bounded waits outside that lock; initialization observes cancellation before resume and retires its pending record even on failure. A close racing with construction must not miss that carrier. Database callbacks, process teardown and thread joins stay outside the lock. Do not add another timer or retry loop. Service close prevents new carriers, closes active ones and waits for bounded teardown. Keep Linux caching, max-agent accounting and timer behavior unchanged.

## Explicit process scope at the two consumers
Change the internal `pinned_ssh(...)` entry to a context manager yielding the same minimal process contract (stdin/stdout, poll/wait/kill). Update both production callers: `_SSHProbeTransport._ssh`/enrollment and `SSHProcessTransport.__call__`, plus their actual fixtures. The shared ssh_exchange continues bounded IO, pipe closure and process reap. The surrounding context owns Windows broker/job/temporary ciphertext cleanup even if exchange never starts or raises. No dynamic cleanup attributes, private Popen internals or __del__ reliance.

Windows spawn uses public CreateProcess with suspended primary thread, explicit pipe handles and a non-inheritable KILL_ON_JOB_CLOSE job. Assign before ResumeThread. Expose only the narrow process methods required by existing exchange; do not create another transport loop. Parent pipe ends are non-inheritable; child inherits only its intended stdio through an explicit PROC_THREAD_ATTRIBUTE_HANDLE_LIST. Pinned [pywin32 b312 win32process.i](https://github.com/mhammond/pywin32/blob/b312/win32/src/win32process.i) exposes STARTUPINFO, not STARTUPINFOEX/attribute lists. Use a narrow typed ctypes CreateProcessW + STARTUPINFOEXW/InitializeProcThreadAttributeList/UpdateProcThreadAttribute wrapper, preserving the primary thread handle for ResumeThread; do not infer wrapper support or use Popen private attributes. Explicitly delete the attribute list and close duplicate child ends after spawn, including failure. [Microsoft HANDLE_LIST contract](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) requires listed handles inheritable and bInheritHandles true; the explicit list, not that boolean alone, limits inheritance. A Windows concurrent sentinel-handle test must demonstrate unrelated inheritable handles are absent from the child before product adoption. Closing the scope terminates/reaps the owned job and stops the same-process broker. Normal/exception/timeout/cancel/service close all converge on this scope. A controller hard kill closes the job handle and terminates the actual helper that may hold the password, as measured in Stage A.

## Minimal implementation seams
The low-level module owns only a concrete `WindowsSSHProcess(args, env, *, cwd=None)` context manager. Construction uses the explicit handle list and creates the process suspended/assigned; `resume()` is explicit. It exposes `pid`, a non-owning original process handle for identity checks, stdin/stdout, poll(), wait(timeout), kill() and bounded close(). The primary thread handle stays private. Context exit closes the job, reaps the process and closes pipes/handles; no vault, ASKPASS, deadline policy or remote job logic enters this module. Its Windows tests must reject inheritance of an unrelated inheritable sentinel and prove simultaneous processes do not cross their stdio.

The credential layer owns the lease, per-invocation slot/pending record, cipher files and one-use broker. It constructs the low-level process, starts the bounded broker, checks its close/authorization boundary, resumes, and yields it under an explicit scope. The coordinator-owned pinned_ssh and two consumers integrate this scope and pass the same absolute deadline. Root and standalone core packaging install the fixed helper with Windows-only dependencies. Windows verification installs only the built core wheel into a new venv, outside the repository with PYTHONPATH cleared; the actual helper must belong to that new environment, and real authentication must not borrow the probe entry point.
