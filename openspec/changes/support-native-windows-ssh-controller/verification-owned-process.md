Thus the first native failed creation independently reproduces the +7, whereas repeated product attempts show no additional global growth. The exact Windows resource types remain unknown; this is not a claim of harmless caching or complete OS-internal diagnosis.

The cold global-equality oracle assumed that failed native creation cannot initialize any process-wide handles. The independent control falsifies that assumption. Replace that assumption with strict ownership checks, not a numeric allowance: capture the actual Job handle, both parent pipe handles/file objects and each child-end duplicate acquired by each constructor. Immediately after its expected failure, before any subsequent OS allocation or attempt, verify every owned raw handle rejects GetHandleInformation with ERROR_INVALID_HANDLE and both file objects are closed. Require the expected ownership inventory (one Job, two parent streams, three child duplicates), and repeat for all three attempts. Capture wrappers invoke each real acquisition exactly once; they retain only raw integer handles or already-owned file objects, never duplicate resources. Check last-error without contaminating the original exception.

Retain the cold per-stage global counts and both fresh controls as diagnostic output, without subtracting seven, GC, warm-up or changing the baseline. Also retain strict equality between the completed first and subsequent attempts to detect repeated growth. The original cold-count failures above remain recorded; this revised gate is pending independent design review and actual Windows execution, and does not by itself validate the full credential carrier.
