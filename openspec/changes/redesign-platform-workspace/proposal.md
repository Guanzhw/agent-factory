# Proposal

## Why

成员进入应用前需要穿过偏重运行机制的底座页面，资源页又将服务器、凭据、工具与租约堆在长页面中。用户已选择浅色侧栏工作台，要求保留真实能力与研究应用边界，改善约 20 人团队的日常进入、配置和跟进任务体验。

## What Changes

- 以选定图的浅色侧栏、蓝色主行动、应用入口、本人任务与两行资源摘要重做底座首页；所有数据来自现有 API，默认无应用时保持真实空态。
- 统一侧栏、资源入口、模型/连接主要配置页的排版和控件；资源按用途分组，保留现有高级连接、租约、共享和撤销入口。
- 保留当前页、查询路由、刷新/历史导航与研究返回来源；收敛重复技术说明，清理残留演示和审批文案。
- 桌面和手机均能完成导航和配置；保存、失败、未确认状态及重复点击保护保留。

## Capabilities

### New Capabilities

- `member-workspace`: 成员底座的真实应用/任务/资源概览、资源分组、上下文导航及响应式可用性。

### Modified Capabilities

无已落入 `openspec/specs/` 的能力；相关历史 change 的浏览器返回、成员资源接入与权限约束继续遵守，不重写运行时契约。

## Impact

范围限底座 `web/` 的展示、组合与导航、相关前端测试和浏览器验收脚本。优先复用现有 React、Tabler 图标及 API，不新增组件框架、接口、认证功能或模型调用。

规范调查基线为 `768e4adcb0e218f9ec27b81e5627db1fb3f21034`；产品实现必须等待登录 PR #150 最终合入 main 后更新基线。本变更不修改认证逻辑，不改 Research 业务工作台，不部署用户电脑。既有用户合并授权适用，在独立审查、浏览器和 CI 通过后合入。
