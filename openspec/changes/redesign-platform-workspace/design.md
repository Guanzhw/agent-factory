# Design

## Context

动机见 proposal。选定浅色侧栏参考图已直接查看，图像 SHA-256 为 `43c2d7a36dfc93f8a60e390a1c36da5a8104c645f54bb59af4eae91f579e3e62`；它是视觉目标，状态文字为示意，不能当真实数据。参考图和内部资料保留在 Library，不加入公共仓库。

当前 `Workspace` 管理会话内导航、任务轮询和错误；`ApplicationCatalog` 仅接收静态安装入口。默认组合为空，Research 组合单独注册入口。资源页已有真实模型、SSH、凭据、工具和远端服务控件；连接空页同时展示多类表单。现有侧栏高级入口已默认折叠。调查基线为 main `768e4ad`；产品实施前已更新到最终登录合入 main `3ec76ad34a97c3803933df646fd30966d4019024` 并核验 CI。

## Goals / Non-Goals

**Goals:** 按图实现浅色侧栏、宽应用入口、本人任务和两行资源摘要；把主要配置页整理为同一视觉层级，保持功能、真实状态、来源和可恢复操作。

**Non-Goals:** 不改认证逻辑、Research 业务组件、后端执行/API/权限；不新增用户系统、任务数据、付费调用、组件框架或设计引擎。现有 F 品牌及 Tabler 图标复用，图中 A 图标不构成重命名。

## Decisions

1. **结构和 token。** 白色内容区、约 256px 浅色侧栏，主色 `#245FEA`、正文 `#15243A`、次级文字 `#64748B`、线条 `#DFE6EF`、侧栏 `#F6F8FC`；正文 14–16px、桌面主标题 36px/分区 26px、首页主按钮 18px 字号/58px 高，其余按钮至少 40px，手机主要触点至少 44px。桌面首页按图依次应用、任务、资源；手机改为顶栏与可展开导航并单列内容。token 限定底座壳，避免更改 Research 继承样式。直接整理相关既有 CSS 声明，删除被替换的重复规则，不追加多套覆盖兼容层。
2. **首页组合。** 保留目录展示边界，组合层复用 `WorkspaceContext.jobs` 的当前成员任务/加载/错误；新首页组件负责任务摘要及模型/SSH只读摘要。复用 `ownerModelApi`、`personalSSHApi` 的 capability/list，不读秘密、不 verify、不创建任务。摘要分别管理加载/失败/禁用，刷新沿用工作区刷新触发，用户变化/卸载时取消旧读取；默认模型必须实际有效，服务器区不把登记当验证成功。没有应用时不显示 AutoResearch 主按钮。
3. **资源分类与原请求入口。** 继续使用现有 query 路由，添加受限 `resource` 值 `servers/credentials/tools/remotes/advanced`，模型保留 `tab=models`。资源首页用明确用途入口，连接页只挂载已访问面板，非当前分类使用 `hidden` 保留状态并隔离焦点；owner 变化时重建，资源 revision 仍刷新已访问面板。高级组保留可信登记、连接引用和租约。受限 query 值参与读写/相等判断，未知值归一到默认分类。远端凭据的原恢复标识已持久化，但父页面的目标与表单开关未持久化；跨页或刷新后需依据本 owner 的原 opaque 标识显式显示仅核对原凭据回执入口，不要求重新填写目标。复用现有 `CredentialForm` 的 owner 范围回执读取及校验，成功回执可恢复目标信息，不自动保存/配置，不保存秘密，不建立通用恢复框架。
4. **来源与导航。** 不新建路由器或来源存储。沿用 `modelReturn` 与应用 query 指针；侧栏资源、任务等日常查看保留合法来源，明确返回平台/选择应用时清除。Research composition 在既有导航边界为从应用进入任务的动作补来源，业务工作台组件无需改动。底座页内返回按钮按合法来源显示应用名称，任务详情也提供返回原应用。通用代码只读 navigation 定义，不依赖研究模块。
5. **配置反馈。** 表单保留现有输入和提交逻辑；用合适宽度、分组、标签、状态区与关联说明提升可读性。协议、已有凭据、服务器主机身份等必要字段不删减或强制改默认值；旧演示说明删除，任务“审批”改为实际待处理/状态说明。保存/撤销/共享的原锁、幂等请求和核对逻辑原样复用。
6. **验证与独立审查。** 规范先非作者审查，实施后完整 diff/简洁性审查并复审整改。定向测试覆盖真实摘要语义、路由往返/归一、资源分类保留面板与授权入口；运行项目 check、两组 npm audit、Research build和架构检查。真实浏览器使用最终登录版本、隔离 PostgreSQL、真实密码普通成员；检查桌面/手机页面、当前页/前后退/刷新/重复点击/退出，实际配置保存和失败。可保存无认证的隔离本地模型配置来验证持久化，但不发模型请求；无效/断网不伪造 API。原研究项目任务返回可用空项目/任务指针做导航测试，不能把它宣称为研究执行成功。

## Risks / Trade-offs

- 新首页读取与用户切换竞争 → 工作区按 owner 重建，读取取消并丢弃过期结果，错误不当空态；已有全局同步状态不能代表摘要成功。
- 分类隐藏导致未确认操作丢失 → 保持现有面板生命周期/恢复标识，专测切换和刷新，不引入自动提交。
- 全局样式影响 Research → 底座局部 token；对既有 Research 同视口截图做回归对照，业务文件保持不变。
- 本地空态不足以证明真实模型/主机 → 验收记录明确数据层与外部调用界限；运行次数和付费请求保持零。
- 登录依赖已解除 → 最终合入版本与 main CI 核验通过后才开始产品实现，登录协议未改。

## Migration Plan

无数据迁移或认证配置迁移。保留原 URL 与权限归一规则，新资源参数可省略。通过审查与 CI 后以独立 PR 合入；回滚仅还原本次前端变更。用户允许完成后在本地或受支持的云端环境验证，本任务交付精确版本、构建/启动步骤和必要配置并只读核查云端能力；回环隔离服务不视为用户可访问部署。不提前部署半成品，不操作用户电脑、创建生产凭据、删除旧文件与数据，或自行引入隧道、付费托管和匿名公开访问。

## 指定设计技能的应用

仓库缺少指定的 ui-ux-pro-max 与 `.impeccable` 技能文件，因此只读官方说明，没有安装技能、运行未知脚本或安装全局工具。

- [ui-ux-pro-max 官方技能](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/tree/28b3b8dee8c976df4fa3e94aed4e092ad43fcb03)：应用清楚的阅读层级、统一 token、移动触点、对比度与可见焦点规则；使用已有系统字体/Tabler图标，不生成额外设计引擎。
- [Impeccable 官方准则](https://impeccable.style)，核对[官方源码版本](https://github.com/pbakaus/impeccable/tree/6743a347db6229848348024388033e830ae4af42)：按该固定版本实际读取的 operate/shape/distill/clarify 原则检查页面（一个技能及其子命令说明，只读应用准则）；将低频抽象放入明确资源分类与高级记录，显示真实空态/错误，压缩装饰，保护 Research 的独立样式。
- 以上规则经真实图像审查落实为五处具体整改，记录在 design-qa.md；不是宣称运行或安装了这两个技能。
