# Design

Add optional `sourceContentIds` to ContentPublication. Missing field in historical rows means no dependencies. New publication verifies the author's current access to every source, includes each source's already flattened original dependencies, deduplicates and stores the complete immutable set. Sources must already exist; the new ID is created afterward, so no graph editor or cycle machinery is needed. Apply the existing 16 KiB bounded-JSON limit to this set; fail explicitly rather than truncating dependencies.

The original request fingerprint remains based on the caller's exact input, before expansion. Same-key replay reads the stored publication and rechecks current dependencies; it cannot return an old private body after withdrawal. Dependencies are never changed by visibility updates. Core validates ordinary sharing permission and active ownership for both the publication and every source; public/team visibility never overrides a source denial. Every read, list, artifact and publication replay uses this check. A denied source makes direct body/artifact reads fail and list omit the derived record. Do not return a partial summary or artifact metadata after denial.

Source-dependent snapshots and sharing changes use the existing admission transaction lock. Lock order is admission then governed content write; nested callers must reuse the existing transaction. Read bounded DB bytes while authority is admitted, then return/encode outside the lock. No file/network I/O, await or compression under it. Barrier tests define the linearization: withdrawal committed before read admission denies, an already authorized snapshot may finish. Existing callers and SQLite fixtures must be checked for lock/transaction compatibility.

The owner may still make their own publication personal after losing source access. Its sharing response returns only id/owner/visibility/createdAt plus `contentState=source_unavailable`, not body, artifact references or dependency IDs. This is an explicit successful sharing receipt, not a swallowed storage error. Only expected authorization/not-found denials trigger redaction; integrity/DB errors propagate. Normal readable responses preserve current shape.

The application remains responsible for identifying all actual model-input dependencies and passing them when publishing selected artifacts. Core expansion prevents a referenced derived publication from laundering its own sources. No global tracking of arbitrary copies or claims to revoke already downloaded data. Tests cover direct/list/artifact/replay/sharing routes, nested-source flattening, missing/foreign/private sources, author/member disablement, and the concurrent withdrawal boundary. Real P7/P8 consumer validation remains separate.
