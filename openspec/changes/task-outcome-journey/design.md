# Design

## Context

参见 proposal。`TaskWorkspace.tsx` 已有分页、错误、产物、允许动作和技术记录；`ControlRecovery.tsx` 当前全局读取，而 `api.controlCommands(owner, taskId, …)` 已支持任务过滤。`App.tsx` 合并导航参数，Research 的会话/项目指针会保留，但没有显式任务来源；`SchedulesPanel` 所选计划只在组件状态中。不能根据残留参数或任务的 `planId` 推断来处。

## Goals / Non-Goals

**Goals:** 用现有数据完成“看结果→处理需要我做的事→返回”的连续路径，保留失败、未知和真实停止边界。

**Non-Goals:** 不构造统一模型结果转换、任务重跑、路由框架、审批/角色系统或后台能力；不重做 Research 业务工作区，不更改工作流输入契约。不改旧 UI 工作区、冻结候选及数据。模板分类与创作、维护子页、部署继续后续片；内部 Research 运行定义不能因有发布记录就变成日常模板。

## Decisions

1. **已有信息重新分层。** 首屏保留目标、状态、错误、实际待处理要求和操作；完成后紧接产物及现有验证说明。完整事件、指标、引用、无待处理项的工作流/委托详情用已有 `details` 样式展开。真正需要输入/决定或核对外部停止的工作流内容保持直接可见，不能为了“简洁”藏掉下一步。删除全站重复的正常 `runtime-strip`，保留状态读取失败/失联信息和任务页真实执行上限，不新增指标。
2. **原操作继续复用同一组件/API。** 给 `ControlRecovery` 传可选任务范围，过滤服务端查询与本地待核对指针；详情动作旁显示当前任务回执，未选任务时显示全局回执。选中任务仍有“查看全部待核对操作”返回列表入口，不创建两套轮询或恢复协议。`canDispatch`、acknowledge 和原命令 ID 沿用现有含义；GET404 仍未知，不能用缺失回执推断未执行。组件在 owner/task 切换时不短暂显示另一范围的旧回执。
3. **显式来源，而非猜测关系。** 复用 `WorkspaceRoute`、URL 查询和组合层，只增加任务返回标记及其目标 taskId、计划指针这几个所需字段，不存整个任意 URL 或任意 JSON。来源仅在 Research 的“查看原任务/子任务”和计划的“查看本次运行”点击时创建；标记绑定当前 taskId。研究组合层解释已有研究指针并提供返回动作，core 不识别 Research 名称、私有表或 session 字段。任务列表新选任务、普通侧栏导航清除来源标记；详情内打开另一任务也不冒称它有同一来源。刷新/前进后退恢复 URL 中明确来源；缺标记、taskId 不匹配或未安装来源时提供“返回我的任务/应用”。任务详情读取被拒绝时不把来源文字当作可访问证据。
4. **计划返回读取原计划。** 计划历史打开任务时保留确切 scheduleId；返回后仅 GET `inspect/occurrences` 恢复选择，不重新提交计划、恢复旧编辑草稿或按 planId 查询关系。来源仅导航，目标继续现有所有权检查；失效/无权访问时显示可恢复读取错误及返回计划列表。计划分页与历史沿现有契约，不新增后端字段。
5. **明确操作后果。** “请求停止本次执行”沿现有 cancel 原命令；已接收、停止中、停止确认分别显示。计划按钮“暂停后续计划/恢复后续计划”旁说明不停止已创建执行；任务停止不改变计划。远端定时不支持和未知准入仍如实展示，不补一个成功按钮。

## Design Guidance

实际读取官方固定版本的 [ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/28b3b8dee8c976df4fa3e94aed4e092ad43fcb03/.claude/skills/ui-ux-pro-max/references/quick-reference.md) 与 [impeccable clarify](https://github.com/pbakaus/impeccable/blob/6743a347db6229848348024388033e830ae4af42/skill/reference/clarify.md)、[distill](https://github.com/pbakaus/impeccable/blob/6743a347db6229848348024388033e830ae4af42/skill/reference/distill.md)，未安装或运行其脚本。应用在：一致的任务名称、错误旁的恢复动作、空态下一步、去掉重复说明、次级技术信息展开；保留已选浅色侧栏和当前字体/间距，键盘焦点不遮挡、手机不靠 hover、操作触区沿现有移动样式。不会为本片建立新的设计系统。

## Acceptance

完整验收的补充范围：`455506f` full `40806050019` 的 PostgreSQL 测试及完成核验真实失败；普通 Checks 注解未定位具体用例，不能当作偶发通过。复用 `check_python` 已有失败注解，使 `check_postgres` 也报告实际失败用例；无 unittest 错误但 required acceptance 未通过时报告既有摘要。只改两个 runner 和对应合成回归，不改发现、选择器、accepted、断言、期限或产品执行，不读取/转存被拒日志。本地原候选复现与新诊断候选分别保留，诊断完善不等于旧根因已修复。

- 真实隔离 PostgreSQL、现有临时密码认证和实际浏览器：空列表→应用；有任务的会话/项目→原任务→同一来源，刷新/前后退不创建任务；成功/失败记录、分页读取与详情重试；桌面 1440 和手机 390，320 关键操作无横溢。
- 实际本地可停止进程或已有原生测试任务：请求停止、重复点击、回执核对与结果显示；若响应丢失/UNKNOWN 需注入，明确记录注入边界。直接服务端拒绝与客户端禁用分别验证，不用 mock API 宣称真实停止。
- 已有本地可执行计划：暂停后续→原执行仍在→查看本次运行→独立停止→返回原计划仍暂停→明确恢复；刷新返回只读取。无 taskId 的 unknown 记录不出现任务链接。测试创建只在隔离库，不触碰真实长期计划。
- owner 切换/退出、来源缺失或篡改、回执暂缺、不可恢复失败、真实待回答/工作流要求的组件反例；至少一个真实浏览器拒绝/失联样例。截图必须来自最终产品候选，不用旧图和测试数量代替可用性；证据区分真实后端、脚本模型和网络注入。

## Risks / Trade-offs

- 通用任务只有现有产物，不能显示所有应用的完整回答 → 明确无产物，真实入口可返回原应用；统一结果契约留后续。
- 折叠可能遮住待处理要求 → 按真实工作流数据决定展示，回归待输入/外部停止案例，不新造状态机。
- 来源字段是导航指针，不能证明资源关系或访问权限 → 只接受现有受支持页面/指针格式，目标照常授权；无可靠来处不用浏览器 `history.back()` 冒险离站。
- 新片依赖 daily 候选尚待发布 → 独立分支保留，合并前核对基线/tree；不修改冻结候选。

## Migration Plan

无数据库或历史任务迁移，既有深链接继续可读。按独立方案审查→前端实施与真实旅程→完整累计 diff/simplicity 复审→准确 head full CI→既有发布门禁推进。回退仅撤本片前端行为，不删除任务、计划或原回执。
