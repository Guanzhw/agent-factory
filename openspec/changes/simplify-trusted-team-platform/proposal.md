# Proposal

## Why

现有框架把成员身份、资源归属、工具注册、计划审批和运行控制混在多条执行链中，增加了小团队使用与扩展成本。用户已确认采用可信团队模型：管理员只管理账号，成员可以调用工作流和组件并自行接入资源，本次按该边界完成代码、历史数据兼容和真实表面验收。

## What Changes

- **BREAKING**：细粒度资源角色授权收敛为有效成员身份；管理员只拥有账号管理权限。账号禁用、私人会话与凭据隔离继续生效。
- **BREAKING**：删除可执行的计划审批、发布审批、审批期限和相关重复静态证明；旧审批仅保留为可读历史数据。
- 所有者直接发布、修订、撤回和归档自己的材料、应用及连接；团队成员可以使用公开版本或复制为自己的版本。
- 成员自行配置模型、HTTP 服务、MCP、CLI 和 SSH，取消地址、端口和部署预注册许可限制；协议确需的身份和语法校验仍在输入边界完成。
- 资源具备个人或团队可见性；团队调用使用所有者保管的凭据，调用方不获得秘密。撤回共享后阻止后续调用。
- 通用 SSH 接入和默认加密凭据保管归平台所有；科研环境准备由科研应用提供。
- 收敛一次执行的准入责任，同时保留预算、超时、取消、连接撤销和防止未知效果重复执行的记录。
- 用 OpenSpec 记录此次已开始的重构，主代理作为 coordinator 按独立任务分配实现、审查与验收。

## Capabilities

### New Capabilities

- `team-membership`: 有效成员、仅管理账号的管理员、历史管理员迁移和原生身份入口的权限边界。
- `member-resource-onboarding`: 成员自助接入已支持协议的资源、默认凭据后端与平台独立启动。
- `resource-sharing`: 所有者管理个人或团队资源，跨成员调用与凭据隔离、共享撤回。
- `member-publication`: 成员直接管理自己材料和应用的发布生命周期，以及历史审批读取。
- `member-execution`: 无计划审批的执行准入、单次静态校验、运行控制和动态工具接入。

### Modified Capabilities

当前项目首次初始化 OpenSpec，没有既有能力规范；上述规范记录已确认的目标行为。

## Impact

涉及平台身份与账号接口、材料/应用、连接/模型/工具/SSH、原生执行装配、科研调用方、浏览器界面和对应测试。旧审批配置需要移除，已有用户、资源、任务、审批历史和效果记录保留；旧全局管理员需迁移到仅管理账号的标记。

本变更的验收集中于权限与资源边界，以及实现这些行为所需的通用能力解耦。科研多轮实验闭环、任务列表分页和多应用运行时组合是先前评审识别的独立产品问题，保留为后续工作。本次实现和验收结果见 `tasks.md` 与 `verification.md`。
