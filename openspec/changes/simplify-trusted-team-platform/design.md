# Design

## Context

动机与产品边界见 proposal.md。原主线 `0fac6de` 已默认成员自发布，但仍保留五种计划策略、三种发布模式、多处原生角色调用和重复执行证明。通用 SSH 由科研装配构造，CLI/MCP 接入依赖部署预注册，模型端点仍有地址限制。

本变更在 `refactor/trusted-team-platform` 隔离分支上已部分实施后引入 OpenSpec。当前代码属于进行中状态：已有针对性验证，首次全量便携检查仍有旧契约测试失败与集成缺口；具体通过数以后续验收记录为准。原始 `D:\CodeSpace\agent-factory` 工作区与其数据不作为测试环境。

## Goals / Non-Goals

**Goals:**

- 一个当前成员检查入口、一个仅管理账号的管理员标记，以及明确的资源归属检查。
- 用户输入在边界规范化，持久化配置可恢复；调用链直接消费已建立的内部契约。
- 将当前修改纳入按任务编号划分的协调、实现、独立审查和验收流程。

**Non-Goals:**

- 本次保留原生执行框架和现有外部效果核对机制，不另建调度器或通用权限框架。
- 科研迭代闭环、任务分页及多应用服务组合按独立变更评估；通用资源接入在本次与科研依赖分开。

## Decisions

### 1. 原生身份保留，资源授权收敛

使用现有账号目录保存成员与禁用状态，采用 Agno 支持的授权 provider 扩展允许普通功能；账号管理经单独路由检查管理员标记。保留原生用户隔离。拒绝用于取消隔离的全局通配探测，并封闭服务账号/PAT 这一绕开当前目录状态的路径。

独立审查已通过原生 API 复现过通配探测可生成全局令牌的问题，因此必须验证实际原生入口，不能只测试平台封装 API。已有自定义全局管理员一次性转换为账号管理标记，用持久迁移状态避免之后降权被重启恢复。

相比给每种原生资源重新建角色矩阵，该方案直接表达已确认的团队模型；相比关闭身份检查，它保留账号禁用和私人数据归属。

### 2. 资源配置与凭据分别持久化

模型、远程服务、工具和 SSH 保存公开配置描述；秘密仍由加密 vault 按所有者、引用和版本解析。正常入口自动创建本地持久主密钥与 vault，显式组织 vault 继续可注入。主密钥文件必须与数据库一起备份，不能在重启时重新生成已有密钥。

HTTP(S) 地址只做语法和协议身份处理，接受本地、私网、IP 与自定义端口/路径；TLS 继续验证目标身份。无需认证的协议调用不要求占位凭据。SSH 验证只确认连接和目录，科研准备检查由科研 package 提供；有效私钥采用已支持 SSH 解析器的能力边界，而不因团队权限策略排斥账号或地址。

动态 CLI/MCP 配置持久化到资源记录；启动时装入绑定注册，其他工作进程按缺失 adapter ID 从持久记录加载。材料与应用验证使用当前实际工具描述，删除另一套许可注册链。

### 3. 共享仅增加个人/团队状态

用小型资源共享记录按资源引用保存所有者与可见性，旧资源无记录时为个人。所有者控制修改与共享；调用成员和凭据所有者分开传递。已有用户连接表按调用者拥有连接别名的契约保持不变，共享模型可以生成调用者自己的连接引用。

共享资源的展示不返回所有者凭据引用；实际调用边界重新读取共享、账号和凭据状态，以处理保存的句柄、共享撤回及凭据轮换。没有新增任意角色、继承、策略语言或管理员资源覆盖逻辑。

### 4. 发布与计划审批整体退役

材料和应用按作者直接管理，公开内容被其他成员复制时建立新身份。旧审批写 API 明确停用，历史记录按原归属读取。运行配置采用当前传入配置，旧审批配置表留作历史，不再充当启动和执行凭证。

计划执行保留成员、归属、运行状态与当前资源检查。删除当前审批模式查询、审批期限、审批创建/决定，以及同进程重复读取和重编译静态 manifest。原始请求幂等、未知效果核对、产物字节身份、预算和取消检查有实际消费者，继续保留。

### 5. Coordinator 拥有状态和验收，子代理拥有明确文件

主代理维护 OpenSpec 和任务状态，确认依赖与文件所有权，再派发实现。已有工作按新任务编号继续，不倒退重做。实现者提交源代码变化、测试命令与结果、未验证假设；独立审查者用新上下文检查最终源码。主代理核对实际结果后勾选任务。

跨任务问题由主代理决定归属，再交给对应实现者。任务不能通过新增兼容分支来保住已被需求删除的行为，也不能以删除仍有效测试来获得通过。真实失败和旧契约断言分别记录。

## Risks / Trade-offs

- [原生旁路] → 原生组件、工作流、会话、服务账号、队列及历史 PAT 必须做实际 API 验证。
- [共享混淆调用者与秘密所有者] → 使用两名成员验证实际模型/MCP/SSH 调用、响应脱敏及撤回后的旧句柄。
- [本地 vault 密钥丢失] → 密钥持久化、原子创建和重启恢复测试；文档给出同库备份要求。
- [历史配置阻止启动] → 使用包含旧审批数据的数据库验证启动和只读历史，保留原内容与身份。
- [移除静态证明时误删运行控制] → 对取消、预算、重试、未知效果和跨工作进程动态工具做针对性回归。
- [Windows 覆盖不到 POSIX 与 PostgreSQL 流程] → 使用任务专属 WSL Python 环境和隔离 PostgreSQL；普通 Windows 测试的跳过不算覆盖。

## Migration Plan

1. 保存隔离分支和原始基线，记录 OpenSpec 引入时的未完成项；用户原工作区不参与迁移。
2. 完成账号标记迁移与 native token 入口修复，移除旧审批配置的执行消费者。
3. 启用默认 vault 与通用接入，共享记录默认个人；已有资源、任务、审批和效果表保留。
4. 迁移 API/页面/应用脚本与测试到成员契约；旧审批写接口返回明确停用状态。
5. 运行静态检查、便携测试、真实 PostgreSQL、独立核心包启动及浏览器成员/管理员两种流程，并进行独立审查。
6. 完成验证后记录提交和回滚边界。若将来部署回退到旧代码，需恢复与该代码版本配套的数据快照和 vault 密钥；本次仅本地实施与验收，不操作现有部署。
