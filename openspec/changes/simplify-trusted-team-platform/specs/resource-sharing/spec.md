# Spec Delta

## Purpose

为模型、工具和服务器提供一致的个人或团队共享行为，使团队成员能复用资源能力，同时由原所有者掌握配置与凭据生命周期，并让共享撤回立即影响下一次资源调用。

## ADDED Requirements

### Requirement: 资源由所有者管理共享范围
系统 SHALL 为成员资源提供个人与团队两种可见性，已有资源默认为个人；只有所有者可以修改配置、共享范围或撤销资源，管理员标记不提供覆盖权限。

#### Scenario: 默认私人资源
- **WHEN** 成员创建资源或升级已有资源
- **THEN** 资源默认为个人可见，其他成员及账号管理员不能读取私人配置或修改该资源

#### Scenario: 所有者开放共享
- **WHEN** 所有者将资源设为团队可见
- **THEN** 有效成员可以发现和绑定该资源，而修改配置与撤销共享仍由所有者完成

### Requirement: 团队调用保留凭据所有权
系统 SHALL 在团队调用中分别记录调用成员与资源所有者，使用资源所有者保管的凭据访问目标服务；调用方的任务和连接记录仍归调用成员所有。

#### Scenario: 另一成员调用共享模型或工具
- **WHEN** Bob 在自己的任务中调用 Alice 共享的模型、MCP 或 CLI 工具
- **THEN** 目标调用使用 Alice 的凭据，Bob 的任务归属保持不变，Bob 的响应不包含秘密或 Alice 的凭据引用

#### Scenario: 另一成员使用共享 SSH
- **WHEN** Bob 使用 Alice 共享的 SSH 服务器
- **THEN** SSH 连接使用 Alice 的凭据，调用和运行控制仍记录 Bob 的身份，Bob 不能导出 Alice 的私钥

### Requirement: 撤销与禁用在下一次调用生效
系统 SHALL 在资源实际使用边界检查当前共享状态、调用成员状态和凭据可用性，拒绝已撤回的共享、已禁用成员或已撤销凭据继续发起调用。

#### Scenario: 已缓存句柄遇到共享撤回
- **WHEN** Bob 保留一个先前取得的共享资源句柄，Alice 撤回共享后 Bob 再次调用
- **THEN** 调用被拒绝，不向目标服务发起新的操作

#### Scenario: 撤销凭据
- **WHEN** 所有者撤销共享资源使用的凭据
- **THEN** 该资源的后续调用失败并明确呈现凭据不可用，系统不回退到其他成员或其他资源的凭据

### Requirement: 共享管理可通过页面完成
系统 SHALL 在资源页面清楚显示资源归属和共享状态，让所有者修改共享范围，让其他成员绑定团队资源，并保留原请求的恢复能力。

#### Scenario: 页面共享与绑定
- **WHEN** Alice 在页面共享资源，Bob 登录自己的账号查看资源页面
- **THEN** Bob 可以绑定资源而无需重新输入 Alice 的凭据，并且看不到修改该资源的所有者操作
