# Spec Delta

## Purpose

让成员直接配置和使用平台已支持协议的模型、工具与服务器，把资源接入变成可检查、可使用的产品能力，并使通用连接和凭据保管不再依赖科研应用的安装或运行环境。

## ADDED Requirements

### Requirement: 成员可自行配置服务地址
系统 SHALL 接受成员提供的有效 HTTP 或 HTTPS 地址，支持域名、IP、IPv6、本机和私有网络、自定义端口及模型 API 基础路径，不要求地址白名单或管理员批准。

#### Scenario: 本地模型服务
- **WHEN** 成员在页面配置 `http://127.0.0.1:8000/custom/api` 并指定模型
- **THEN** 前后端均接受该地址并向所选地址、路径与模型发出调用，连接失败时返回实际失败状态

#### Scenario: HTTPS 自定义端口
- **WHEN** 成员配置使用自定义端口的 HTTPS 服务
- **THEN** 调用保留端口及正确服务器身份，继续校验 TLS 证书

### Requirement: 凭据依协议需要提供
系统 SHALL 允许无需认证的受支持服务在未配置凭据时接入；需要认证的服务使用成员明确提供的凭据，凭据不得通过地址字段或诊断输出泄露。

#### Scenario: 公开或内网无认证服务
- **WHEN** 成员连接无需认证的模型、MCP 或远程服务
- **THEN** 系统允许不填凭据并按协议验证或调用，无需创建占位密钥

#### Scenario: 需要认证的服务未配置凭据
- **WHEN** 服务实际返回认证失败
- **THEN** 系统明确呈现该失败，用户可补充凭据后重试

### Requirement: 成员可接入自己的工具
系统 SHALL 允许成员通过 MCP 服务发现选择工具，或配置 CLI 可执行文件、参数、工作目录和输入输出契约，并在应用中调用，无需为每个工具修改部署代码或授权清单。

#### Scenario: 新 MCP 工具进入应用
- **WHEN** 成员发现并绑定一个新 MCP 工具，创建使用该工具的材料和应用
- **THEN** 原生执行路径调用所选工具，服务重启或换工作进程后仍可解析该工具

#### Scenario: 新 CLI 工具执行
- **WHEN** 成员提交合法命令、参数和工作目录，并通过应用调用
- **THEN** 系统在指定目录按参数执行，按声明处理输入输出，执行失败或超时明确返回

### Requirement: SSH 接入独立于科研环境
系统 SHALL 允许成员配置 SSH 域名或 IP、端口、账号、有效私钥和主机身份，完成通用连接验证；科研依赖只在用户准备对应应用时检查。

#### Scenario: 普通服务器连接
- **WHEN** 成员连接没有 Docker、Python 或科研软件的 SSH 服务器
- **THEN** 通用 SSH 验证可以成功，平台不因缺少科研依赖拒绝保存或使用连接

#### Scenario: 应用环境准备
- **WHEN** 用户在已验证服务器上准备科研应用环境
- **THEN** 由该应用检查实际需要的依赖，并报告准备结果

### Requirement: 正常启动提供持久凭据保管
系统 SHALL 在正常启动时提供加密凭据保管，使成员接入资源不需要编写部署侧凭据工厂；重启后已有凭据继续可用，私钥与 API 密钥不进入明文数据库或公共响应。

#### Scenario: 重启后继续调用
- **WHEN** 成员保存凭据、绑定资源并重启服务
- **THEN** 原绑定仍能解析同一凭据，凭据存储与日志不含秘密明文

#### Scenario: 平台独立运行
- **WHEN** 只安装平台包而未安装科研应用
- **THEN** 账号、模型、工具、远程服务和通用 SSH 的接入入口可用
