# Spec Delta

## Purpose

让成员直接管理自己创建的材料与应用，通过明确的作者归属和版本记录支持团队复用，减少发布中的人工审批，同时保留升级前的审批记录、内容身份和已有任务引用。

## ADDED Requirements

### Requirement: 作者直接管理发布生命周期
系统 SHALL 允许有效成员直接发布、修订、撤回和归档自己的材料及应用；这些操作不创建审批请求，也不要求管理员操作。

#### Scenario: 普通成员发布和撤回
- **WHEN** 作者通过页面或 API 发布自己的草稿，随后撤回该公开版本
- **THEN** 发布和撤回立即按请求完成，不创建新的审批记录，版本历史仍可读取

#### Scenario: 管理员不能修改其他作者资源
- **WHEN** 账号管理员尝试修订、发布、撤回或归档另一成员的材料或应用
- **THEN** 系统拒绝该操作

### Requirement: 团队复用保留作者与版本身份
系统 SHALL 允许成员使用公开版本，并将其他作者的公开内容复制为自己拥有的新资源；不得用复制操作覆盖原作者的版本链。

#### Scenario: 从公开资源创建副本
- **WHEN** Bob 从 Alice 的公开材料或应用创建副本
- **THEN** 副本具有新的资源身份并归 Bob 所有，Alice 的内容、版本和任务引用保持不变

### Requirement: 历史审批保持可读且不再执行
系统 SHALL 保留已有审批和版本数据供有权查看原记录的成员读取，停止创建或决定新的发布审批，且旧审批模式不会阻止新版本正常启动。

#### Scenario: 旧数据库升级
- **WHEN** 数据库包含旧审批模式、审批记录和内容版本
- **THEN** 服务可以启动，旧记录仍可按归属读取，成员发布新内容不依赖旧审批结论

#### Scenario: 旧写入接口
- **WHEN** 客户端请求已移除的审批写入操作
- **THEN** 接口明确返回该操作已停用，不执行隐式批准或其他替代写入

### Requirement: 成员工具可以进入发布内容
系统 SHALL 允许作者选择或填写当前已接入工具的声明，在材料和应用中发布使用；工具的输入输出契约在边界校验，不再受固定内置名称或部署许可清单限制。

#### Scenario: 自建工具发布
- **WHEN** 成员接入一个非内置名称的工具并发布对应材料和应用
- **THEN** 页面与服务端接受当前可解析的工具声明，并能将其交给执行流程
