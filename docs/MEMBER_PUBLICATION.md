# 成员发布与团队复用

有效成员可以直接创建、发布、修订、撤回和归档自己的材料与应用。账号管理员负责账号管理；资源的作者归属决定谁可以修改它。

## 材料与应用

在“构建材料管理”创建草稿，检查名称、内容、依赖和来源后选择“发布此版本”。应用管理采用相同流程，应用固定引用已发布材料的 ID、版本与摘要。发布立即完成，不生成发布审批。

作者选择“新版本”或“载入并修订”会保存新的版本。原正文、摘要、历史任务和原有连接绑定继续保留；发布新版本后，成员在新装配中选择它。

其他成员可以使用已发布版本，并选择“复制为新材料”或“复制为新应用”建立自己的资源。副本获得新 ID，后续修订由副本作者管理，原作者的版本链和已有任务引用保持原身份。

作者可以填写原因并撤回或归档自己的版本。撤回后的精确版本不可用于新的执行，已保存的任务、产物和版本正文继续保留。重新发布采用新草稿版本。请求结果不明确时，保留原请求标识重试，以恢复同一次操作的回执。

## 使用成员接入的工具

先在工具连接中接入 CLI 或 MCP 工具，确认当前工具名称、声明能力和组件运行声明。工具可使用自定义名称，无需部署侧许可登记。

创建工具材料时，可在“选择已接入工具”中选择当前 CLI/MCP 声明，页面自动填写名称、能力、输入结构和精确组件声明。“应用中的工具连接名称”默认是 `toolConnection`；应用应声明同名的工具连接需求，装配时再选择自己的个人或团队连接。也可以手动填写当前工具声明，或从已有材料复制。服务端按固定的 adapter ID 和修订核对工具名称及能力；不同作者的工具可以同名。工具的命令、MCP 地址和凭据由资源连接保存。

也可以通过“导入定义”保存工具连接提供的 `runtimeBinding`，并填写应用使用的连接名称，例如：

```json
[
  {
    "kind": "tool",
    "name": "团队样本整理",
    "content": "member_sample_tool",
    "permissions": ["member:sample"],
    "runtimeBinding": {
      "adapterId": "member-sample-adapter",
      "revision": "1",
      "config": {"connectionName": "toolConnection"}
    },
    "license": "MIT",
    "provenance": {"kind": "original", "notice": "Original team material."}
  }
]
```

示例中的工具名称、能力和运行声明须替换为实际工具返回值。编辑或复制材料时，页面保留已有 `runtimeBinding`。将工具材料固定到应用后，使用个人或团队连接进行装配和执行；共享工具继续使用资源所有者托管的凭据。

## API

| 操作 | 材料 | 应用 |
| --- | --- | --- |
| 创建草稿 | `POST /api/factory/material-governance/drafts` | `POST /api/factory/applications/drafts` |
| 发布 | `POST /api/factory/material-governance/versions/{id}/{version}/publish` | `POST /api/factory/applications/{id}/versions/{version}/publish` |
| 撤回 | 对应版本路径下的 `/withdraw` | 对应版本路径下的 `/withdraw` |
| 归档 | 对应版本路径下的 `/archive` | 对应版本路径下的 `/archive` |

写请求携带 `requestId`；撤回与归档还可携带 `reason`。身份来自当前登录账号。创建副本时提交定义并省略 `id`；作者修订使用自己的原 ID，应用也可调用版本下的 `/revise`。

## 旧数据升级

当前发布模式为 `member-self-service`。部署配置中的旧 `separate-admin`、`demo-self-review` 发布模式需要改为当前模式；旧模式作为新运行配置会明确报错。

数据库中原有发布审批、审批配置、版本和请求回执保留原内容与身份。服务启动使用当前传入的运行配置，历史审批配置及其摘要不再充当启动或执行许可。历史审批按原作者范围读取，账号管理员不能查看其他作者的私人历史。

旧审批申请和决定写接口返回 HTTP 410，读取接口继续提供原记录。升级不会把待处理审批改成已批准，也不会自动发布草稿。作者可以通过直接发布入口发布仍有效的草稿；撤回或归档的版本需要创建新版本。

本变更不操作现有部署。日后部署前应备份数据库以及相配套的 vault 主密钥；若回退到旧代码，应恢复与旧版本配套的数据快照和密钥。
