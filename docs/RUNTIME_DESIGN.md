# Runtime

Agno AgentOS 3.1.0 owns the Agent loop, streamed model responses, durable PostgreSQL queue and native cancellation. Factory supplies owner-selected models and native tool functions. There is no separate research scheduler or fixed experiment Workflow.

A conversation turn records its goal, context, model connection and original request. The native run uses that snapshot. Repeating a request reads its existing task; a failed or missing reply is reported as such. This request association supports refresh and correct results without a separate approval or receipt workflow for the user. A definite failure before queue admission ends the turn. A missing acknowledgement triggers lookup of the original native ticket instead of a new submission; background observation also carries an earlier Stop request to a late-arriving ticket.

File, command, memory, research and collaboration tools are available through the same Agent. Personal MCP and CLI registrations are included directly. The installed Agno Workspace handles file replacement. The existing process helper runs local commands, observes their exit and responds to cancellation. There is no default command deadline or project tool-count quota.

Subassistants use independent native queue tasks with parent links. Waiting continues the original native run when its child has a result. Stop requests apply to the task tree and local owned processes. SSH disconnection alone cannot prove that arbitrary remote background processes have stopped.

A small per-run dispatcher resolves the selected model for the current owner. Chat Completions and Responses use Agno formatting and parsing with the official OpenAI SDK. Thin adapters preserve Responses reasoning and phase, match legacy tool-call IDs, and retain nullable tool schemas that Agno 3.1.0 otherwise rewrites. Agno handles compression and summary generation against known model metadata; unknown context windows remain unspecified.

New research turns share their conversation’s native session while retaining separate task and request identities. Agno builds history from native messages without a fixed run-count limit. A per-run history view includes failed and canceled turns, pairs interrupted tool calls with an explicit unknown observation, and imports older task-session messages without rewriting stored runs. Withdrawn sources cut only future model context. Legacy answer-only summaries do not replace the original messages; a new successful summary can compact them.

Research Agents submit through Agno's background streaming route. Factory observes HTTP acceptance, then resolves the exact owner, session, component and idempotency-key ticket. Disconnecting that HTTP observer does not cancel queued execution. Continuation retains the native background HTTP 202 interface and the original ticket's streaming mode. Agno persists run events, including content, for recovery.

The browser starts with a database snapshot, then receives updates from Agno's native event tail and PostgreSQL notifications committed with application changes. Model progress replaces changed event rows rather than rereading the whole conversation every half second. State, source and collaboration changes refresh the canonical view; observation timestamps and queue heartbeats do not. Reconnection rebases from the database and merges event rows by ID. A failed native tail falls back to database notifications without repeatedly rereading the session. Native in-memory streams remain process-local; this does not establish cross-replica streaming. Settings and chat preserve drafts across navigation.

A completed queue ticket can contain a failed streaming run. Factory displays its persisted error or cancellation instead of treating it as a successful answer, and uses the native error event for diagnostics. A queued or running retry still takes precedence over an older persisted run error. Factory does not turn a normally completed streaming error into a new retry policy.

Provider text and visible reasoning keep their original response identities and order. Adjacent text of the same kind is saved as one segment, flushed at most every 200ms and at segment boundaries or completion. Running turns read these records directly instead of copying every text fragment into the conversation row. The final answer comes from the completed native run's last assistant message; Agno's aggregate run content can also contain earlier messages before tool calls. Older terminal snapshots remain intact.

Chat selects an existing model connection and its verified reasoning effort for the next turn. The native plan pins that choice, including delegated work. Unknown model capabilities expose only the provider default. Auxiliary compression and summary requests do not emit chat content or reasoning.

Removed governance, budget, lease and prepared-handoff services no longer gate Agent execution. Historical rows and user files are preserved. Prior platform and Windows acceptance results apply only to the revisions they exercised; current static checks and actual use are recorded separately.

Native Agno Skills loads instructions and references from bundled research skills, the launch project's `.agents/skills`, and optional `FACTORY_SKILL_PATHS` directories. The pinned loader only discovers immediate resources, so a small subclass lists nested files. Script reads remain native; execution uses the existing research command function, preserving arguments, cwd, full output files, cancellation and original-call replay protection. This replaces the SDK's synchronous 30-second `subprocess.run` path, not the Skills model or parser.

Unknown tool outcomes are returned as observations rather than terminating all subsequent tools. Personal tools explicitly configured as read-only do not record new side effects or prevent a native queue retry. Tools not declared read-only retain their effect records, including completed effects, which prevent automatic replay of the whole run. Existing records are unchanged. The native queue state determines whether a run is retrying or ended; the previous attempt's persisted error does not cancel a queued or running retry. An existing unknown call not declared read-only is not dispatched again. Native turn completion and an individual tool's unknown side effect remain distinct: a completed native turn can permit independent work without resolving the older operation. User Stop and active child execution still use actual runtime status. Research records accept ordinary observations and references; analysis can be standalone or linked to an existing record, with no terminal-record prerequisite.

A withdrawn shared source or adopted assistant answer no longer locks the entire chat. A new turn automatically starts a fresh context while preserving the visible history. Earlier replies, corrections and summaries are not automatically resent because they may contain derived source text. A running turn that already depends on the withdrawn source fails before another model request, and its actual native termination still determines when a new turn is available. Ordinary file and command tools do not inherit a project's unrelated source-availability gate. This does not erase information previously copied into user files or personal memory.

A read-only summary provider failure does not terminate otherwise usable research. The turn retains its valid unsummarized history (and any previously confirmed checkpoint), reports the summary failure, and continues without retrying that summary on every tool step. Stop and withdrawn-source checks still apply to primary and auxiliary model requests. If the full valid context exceeds the provider's actual window, its error remains visible; history is not silently discarded to make the request fit.

Published-content reads use the existing content service's actor, owner and dependency checks. Making an owner's record private does not withdraw the owner's access or reset that owner's chat context, and records are not rejected merely because their application label differs from research. Other members still need access to the record and its original sources.

Personal MCP tools reuse a connection within one native execution, scoped to the requesting owner and configured resource revision. Each invocation still resolves credentials and checks the current resource binding immediately before dispatch. While connecting or waiting for a reply, it observes Agno's cancellation signal and cancels the SDK request on Stop; this adds no execution deadline. FastMCP owns the underlying session task; the pinned Agno 3.1 async run finally closes the registered connections on completion, error or Stop. Dynamic tool factories are not automatically registered with that cleanup list, so Factory registers its run-local connection holder there. Discovery remains a separate short connection. No connection is shared across native executions, and an unconfirmed call is not automatically resent.
