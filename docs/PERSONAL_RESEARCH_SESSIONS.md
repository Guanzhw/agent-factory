# 个人研究会话

此入口属于显式 Auto Research 装配。默认 `agent-factory` 仍只启动底座；旧项目、七步研究流程和 QA 保留。自主会话复用 Agno **3.1.0** 的 Agent 工具循环，每次继续产生一个原任务，个人助手和研究会话保持不变。它不会自动从历史任务重放操作。

## 启动条件

先按 [README 的身份验证启动步骤](../README.md#start-with-configured-authentication) 完成现有 PostgreSQL、身份验证及凭据存储配置，并准备浏览器信任的 HTTPS 证书。已有账号可直接使用，不必重新创建。成员在“我的资源”配置自己的模型连接，再进入 Auto Research 的“研究会话”。本入口没有默认账号、模型或凭据。

Linux/POSIX 部署可显式选择本地研究工作目录。目录必须事先存在、为绝对路径，且路径中不能有符号链接：

```sh
export FACTORY_RESEARCH_WORKSPACE_ROOT=/absolute/owned/research-workspaces
export FACTORY_RESEARCH_HOST_COMMANDS=1
# 可选：仅覆盖可执行文件查找路径；默认使用 OS 标准路径，不继承服务 PATH。
export FACTORY_RESEARCH_COMMAND_PATH=/usr/bin:/bin
npm run build:research
export FACTORY_LOCAL_LOGIN_ORIGIN=https://127.0.0.1:3100
uv run python -m uvicorn agent_factory_server.research:create_app --factory \
  --host 127.0.0.1 --port 3100 \
  --ssl-certfile "$FACTORY_TLS_CERT" --ssl-keyfile "$FACTORY_TLS_KEY" --no-access-log
```

打开 `https://127.0.0.1:3100`。证书路径、数据库和签名配置沿用现有安全配置，不能直接把 HTTP 测试服务当作用户部署。`agent-factory-research` 的 HTTP 入口只适用于已经配置 HTTPS 终止代理的环境；上面的 Uvicorn factory 同样读取研究工具配置。

这些参数只启用受控本地工具，不创建 OS 沙箱。命令使用部署进程的 OS 用户权限，仍可能访问该用户可读的其他文件或网络；不能把 cwd、目录校验或清理环境变量当作跨租户隔离。请仅在符合团队信任边界的独立执行环境中启用，不要在有额外敏感文件的服务账户下直接开放任意命令。未配置时界面报告缺项，不默认使用服务源码目录。当前不提供自动依赖安装，也未证明 Windows 本地命令或远程个人 GPU 接入可用。

## 使用与恢复边界

- 创建时填写目标、自然语言停止边界和模型；工具次数、单操作时限是另外的机器限制。费用/token 不计量，未实现 CPU/内存/PID 硬上限。
- 运行中补充先保存，下一次主研究请求才纳入。正在执行的命令不会因补充指令立即改变；“已纳入研究请求”不表示模型已经遵守。
- 停止先返回请求已接收。只有原受控进程组确认结束，界面才可确认本地停止；无法确认的操作保留待核对。
- 刷新或重启后打开原会话不会创建新任务。原请求无回执、未知副作用，以及重试时无法确认原工具历史的操作都不能被新一轮绕过。已确认结束且没有未解决操作的会话可显式继续；新会话的自主协作还可按发问时保留的意图继续，见下文。
- 历史持久保留。下一轮超过 12,000 字符的会话上下文容量时，已授权的新一轮会先用当前成员的模型整理已确认的助手回复，再继续研究；打开、刷新或重启本身不调用摘要。目标、停止边界、用户原文、证据来源和原操作状态不靠摘要替代，也不把研究会话当作个人长期记忆库。
- 共享证据只能来自现有明确发布的研究内容。撤销后，新读取和依赖该来源的后续模型上下文都会停止；已经发出的模型请求不能被撤回。

## 上下文整理与中断

整理复用 Agno 3.1.0 的原生 `SessionSummaryManager`，发生在新一轮的活动任务中。界面显示整理状态和上次成功覆盖的轮次；摘要完成并不表示研究完成，也不表示模型已经遵守纠正。整理期间提交的纠正仍保存为待纳入，进入下一次研究请求后才更新状态。

无效或过长的摘要不会替换已有记录，也不会据此继续研究。整理请求已发出但结果未确认时，不自动重发。原任务结束且没有待核对的业务操作后，可明确开始下一轮再次整理，这可能产生一次新的模型请求；业务操作结果未知时，仍须先核对原任务。

若摘要已保存、原轮次仍在队列中且既有操作守卫允许，服务重启后原生队列可复用摘要继续同一个任务，不再请求摘要。这是恢复已经授权的原轮次；读取页面不会创建新轮次，旧会话或没有待处理自主协作意图的会话仍须由你明确开始下一轮。

这不是无限上下文：摘要最多 3,000 字符，单次待整理内容最多 48,000 字符，保护内容与摘要合计仍须放入 12,000 字符的会话投影。必要原文过大或没有可整理的回复时会拒绝新执行，完整历史仍可查看。字符限制不是模型 token 或费用计量；既有轮次和工具限制仍生效。

验收记录须区分真实模型、真实临时文件/进程、数据库协议 fixture 和浏览器。目标 64GB/30 活跃会话容量、真实 GPU/SSH、完整隔离和研究质量均需要各自的后续证据。

## 从原会话向同事助手提问

在研究会话的“本会话的同事问答”选择同事助手，填写问题并发送。只发送当前问题文本，不自动附带你的会话目标、历史、文件或凭据。对方须已在自己的助手设置中配置问答和可用预算；对方浏览器离线不会阻止已接受任务执行。

已发问题和回复保留在原会话。打开回复可核对原问题、回答、来源及独立的任务状态；回答存在不代表研究已经完成。选择“用于下一轮”后，还须提交你的下一轮指令才会采用该回答。选择或刷新不会启动你的助手。这是人工入口；新配置会话还支持下面的自主路径，旧会话保持其原工具版本。

请求结果未确认时，使用“查询原问题请求”，不要另发相同问题。若查询未找到，可明确点击“按原请求再次发送”，使用保存的原标识与原文本；迟到或已保存的相同请求不会创建第二个任务。对方在“收到的问题”中可打开原问题；仅在系统确认尚无原任务、原配置和预算仍允许时提供“接续原问题”。已有任务即使结果未知也只能核对原任务，不会重新派发。你不能接续或停止同事的任务；停止自己的会话也不停止对方已经接受的问题。

采用后仍会重新核验双方及来源权限。权限撤回时，原会话中的引用正文与来源隐藏，后续模型和工具请求被阻止，原问题标识和历史记录保留；已经发给模型的内容不能撤回。未发送草稿与原请求文本保存在当前浏览器，退出登录清除；之后仍可查询原记录，但缺少原文本时不能按原请求再次发送。

## 助手自主协作

新配置的会话可在目标和运行限制内查询已开放的同事助手并提问，不要求你逐条确认。问题卡片标明是你发送还是助手发送；可打开查看实际文本。工具只发送助手提供的问题文本，不自动复制私人历史或凭据；模型自行写出的文本仍应按实际内容核对。

回复到达后，活动助手在下一模型请求前核验来源、操作状态和容量；正在运行的工具不被改写。卡片分别显示等待回复、待纳入、已纳入或受阻。已收到回答、已创建下一轮，都不等于回答已经进入研究请求。多条已就绪回答可在同一轮使用，既有人工引用保留。

原运行安全结束且没有阻断时，后台可按发问时保存的意图，在同一会话自动创建一次后续轮；界面保留触发它的原问题。对方浏览器离线和你的页面关闭都不取消此意图。页面刷新只读；服务重启后，后台仍可处理已授权意图，所以不能将“刷新不执行”理解成所有后台工作停止。

停止会话会取消尚未消费的继续意图，迟到回复不会自行解除停止。已经提交给同事的问题仍归对方处理，即使其任务尚未创建；停止自己不取消对方的任务。之后手动继续不会复活已停止的旧意图。预算、轮数、来源权限、容量不足或原操作待核对时显示具体原因，不替换资源或无限重试。

重启只核对原消息、回执和任务，不派发已有 RESERVED/UNKNOWN 操作。若原运行已结束，且所有操作都能精确证明为已保存的原提问，可解除该提问的核对阻断，再按原意图继续；含任何其他文件/命令操作时不采用这种自动核对。旧运行状态和结果保持原样，未确认操作不会被写成成功。
