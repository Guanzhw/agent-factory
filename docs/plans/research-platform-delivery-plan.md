# 团队研究应用分层交付规划

2026-10-25，用户旅程与总体验收框架已确认，实施已授权。本文是独立文档分支上的完整产品规划，不是 MVP 删减、已实现声明或真实跨用户数据共享许可。需求原文归纳见 [CONTEXT](../../CONTEXT.md)，概念见 [词汇表](../../GLOSSARY.md)，源码依据见 [底座差距分析](research-platform-core-gap-analysis.md)。PR104已于本轮独立审查及检查后合入main（d2090254ac325b8fea2d0bbe39d7a6efc74b57bc）；本轮实施仍不调用付费模型或真实外部GPU。

## 实施前与合入门槛

已接受[最终验收契约](research-platform-acceptance-contract.md)的总体框架；实际环境与统计参数仍须在正式运行前冻结。契约定义确定性机制、真实浏览器、真实模型团队价值和实际 GPU/部署/容量四层验收；未接真实依赖不能以 mock 通过替代。每个 P0–P9 PR 合入前必须由作者之外的审查者检查相对 base 的完整 diff，给出绑定最终 head 的精简审查结论并完成必要整改。具体规则与验收 ID 统一放在契约中，本文不重复矩阵。

## 用户价值与完整旅程

成员通过自己的研究助手持续研究，让团队已经付出的实验成本转化为可检索、可质疑、可复现的共同经验，同时保持个人工作空间独立。

1. 登录进入自己的助手和项目概览。首次为空时可建立项目、选择已有模型及连接资源，不需要先建立团队消息流或完整 Agent Teams。
2. 与助手形成简短研究约定：目标、评价标准、资源与预算、边界、达标和停止条件。约定不预先固定每一步路线。
3. 助手自主安排多轮实验，按需创建临时实验 agent；复用团队经验。符合已确认约定的逐轮尝试不增加审批。
4. 实验开始即形成团队可见“进行中”记录，自动积累条件和证据，结束补充成功、失败或未确定结果；不发布全部私聊和临时草稿。
5. 团队助手主动发现、通知和关联相关已有记录。成员离线时可以自动回答经验询问，但不能因此开启训练或占用 GPU；关联分析有出处、标明 agent 推断，不冒充实验验证。
6. 用户在项目内调整目标，保留版本和历史证据，助手解释哪些继续、停止或失效，经明确后按新目标继续；无关问题另建项目。
7. 达标、预算/边界触发或有依据判断不值得继续时结束研究。可放弃路线，也可结束整个未达标研究；给出尝试与证据，不能声称证明目标不可能。
8. 交付能复现、继续使用和继续研究的成果：结论、证据、代码、配置、运行方式、负结果与剩余疑问；后来研究可引用这些成果而不改写原作者记录。

非目标：本阶段不造统管所有应用的总 Personal Agent，不做 P2P 集群，不建第二套账户、vault、执行器或恢复器，不迁移不存在的旧 OpenResearch 用户，不自动共享凭据/全部空间，不重做无关视觉设计。研究任务结束不掩盖仍未解决的外部操作 UNKNOWN。

## 当前选择：Factory 为执行基础，OR 为参考与可选适配

根据用户委托的技术评估，规划选择不整体照搬/fork OpenResearch 应用、不将其 Rust executor 抽取为 core 库。优先验证现有 Factory 远程执行能力是否满足个人 GPU 场景，研究应用只拥有研究编排与证据模型。借鉴“实验节点与运行尝试分离”“保留负结果”“进程结果不等于科学结论”；不照抄固定失败次数阈值，遵循用户研究约定。

## 最小通用扩展与瘦接入契约

**身份与消息。** 设计稳定端点 ID，关联成员、应用和可调用组件；一条消息包含不可伪造的发送者/接收者、幂等键与内容摘要、correlation/reply/source 引用、期限、有限 payload。重复同键同内容返回原收据，同键异内容拒绝。传输允许重投，业务准入必须幂等；不宣称跨系统 exactly-once。先落消息及原 request 关联，再经现有准入进入 native queue；丢接纳响应时查原收据，缺失或未知不触发新的执行身份。

**离线唤醒与事件。** 规划默认采用事件驱动有界任务，不为每个助手常开轮询/推理循环。用户离线不影响已配置范围内的 QA 准入，执行主体仍是接收者。新增持久订阅游标、去重和交付状态，复用 task events 作为事件来源；研究相关性与收件人选择留应用。建议同一 PG 事务承接领域记录提交与通用 outbox 写入，接口只接收不透明应用引用与事件，不把 project/experiment 字段加进 core。实施前通过提交/回滚/崩溃窗口验证原子性，不能假设两个 service 调用天然原子。

**权限和预算。** 每次送达、读取和工具调用重查当前权限；引用他人记录不复制其连接授权。接收者自动 QA 使用其已配置模型和受限预算，禁止绑定训练/GPU 操作，从工具/执行入口检验，不能仅写提示词。建议为自动 QA 设有限并发、token/调用额度、TTL、关联深度及去重，防止助手互问成环；具体数值需测量。预算建议由接收者自有 scope 记账，不新增团队钱包；金额不可计量时明确限制，UNKNOWN 用量继续占用承诺。资源不足时可拒绝/延迟并保留可读状态，不隐式充值或借用同事 GPU。

**共享证据。** 应用提交经过筛选的记录及精确产物引用，声明作者、来源版本/hash、条件、状态与证据级别。建议扩展最小内容授权端口，使 core 用当前成员权限检查应用发布策略后返回限定产物；应用不能借 Alice 身份读整个 job 再任意代理给 Bob。策略使用 core 现有成员/共享机制，不自建第二套 ACL。历史引用保留出处身份，访问撤回或成员禁用后的读取行为必须有明确测试；不能把资源共享设置直接当作研究记录共享实现。

**生命周期。** 显式装配应用和关闭钩子，沿用已有有界关闭与原操作恢复。应用研究状态可重建，不能主动重复未知任务。应用卸载后 core 继续启动；原应用未完成任务保留“缺少原应用/待核对”事实，不伪造成功或重新派发。每次运行只有原生执行链/选定后端控制物理效果，消息交付恢复只恢复消息与收据查询。

现有 `ApplicationLifecycle` 和 `ApplicationExecutionContext` 继续作为基础；以上扩展在契约阶段决定必要新增 port，不预先建立大而全 SDK。接口版本、错误码、游标和容量边界必须以可运行非研究 fixture 证明，不凭命名推定通用。

## 研究应用行为设计

研究约定与后续目标修订不可覆盖历史。目标变化采用版本校验，保留旧计划/证据，逐项说明继续、停止或适用范围变化；旧操作停止未经证实，不开始会冲突的新操作。预算承诺随项目关联，不因目标改名、重新登录或恢复而重置。项目可以“未达标结束”，同时显示外部操作仍 UNKNOWN；科学判断终止和资源确已释放必须分开。

每个实验从开始就记录作者、所属项目/目标版本、假设/条件和运行引用，结束写真实指标、失败、取消或未知状态。运行成功只证明程序完成；验证结论需要明确评价标准和可检查证据。agent 推断带来源与标签，不能把推断覆盖为实验事实。同事的关联分析属于其自己的记录，保留原文作者与版本；复核/评论/分支的更广权限尚未选定。

最终成果清单建议包含目标版本、源码 commit、依赖锁、非秘密模型/材料/连接标识、运行命令、数据引用及 hash、环境与 seed、指标和证据、负结果、局限与待研究问题。缺失数据/不可重分发依赖明确列出，不保证任意环境逐位复现。继续研究建立新尝试并使用新授权预算，不把 UNKNOWN 原操作当作“重跑”入口。

前端围绕助手与项目概览，详情提供目标版本、实验/运行、指标、证据和协作下钻。明确区分进行中、进程终态、agent 分析、已验证结论、待核对操作；提供空状态、资源入口、退出重登、直接 URL 和刷新路径。通知筛选与频率尚待确定，不将个人偏好变成所有用户的固定规则。

P2/P3 通用能力与 P4 应用入口可在 P1 契约稳定后分工；核心接口/schema/生命周期交界由集成负责人统一审阅。P5 先评估 Factory 后端，不等待 OR 适配器。每阶段先定故障假设再测，重型测试串行；不在 4 CPU/16 GiB 环境并发完整 PG 污染时序。代码修复后必要完整验收与无改动重复追绿严格区分。

日常按 [开发检查](../DEVELOPMENT_CHECKS.md) 跑相关单元/PG/边界、Web check/audit 和短浏览器；跨状态机集成点运行完整 Linux PG、Windows、独立 core 和真实浏览器，记录精确 commit、退出码、通过/跳过、首次失败和清理结果。合成模型、真实本地进程、真实协议、生产模式本地身份与实际外部服务分别标注。

## 技术默认、待验证与决定门槛

| 事项 | 当前规划方向 | 尚需证据/决定 |
| --- | --- | --- |
| 运行拓扑 | 建议集中 server agents + 个人 remote GPU，单 PG/native runtime | 未测硬件；不能承诺 20 人并发。区分在线人数、QA 并发、训练并发，测 CPU/RAM/队列/磁盘/恢复及失败隔离 |
| 长期助手 | 规划默认：持久身份与记忆 + 事件唤醒有界推理 | 验证唤醒延迟、预算和停用行为，不让“长期”变成常驻重实例 |
| 通信协议 | 规划默认：本服务内持久消息/关联，接口可版本化 | 外部 A2A 协议映射待真实接入需要；不预先选复杂网络栈 |
| 内容与权限 | 实验条件/证据/结论默认团队读，作者编辑，自己的来源分析可追加 | 原始数据、私聊、评论/复核/分支的其他权限未定；保持最小已确认范围，不自行扩张 |
| 记忆与检索 | 有出处、按当前权限过滤的研究内容检索 | 索引/向量方案及删除失效传播需测量；不为“长期”复制所有对话到团队索引 |
| GPU 后端 | 先复用 Factory remote/process/resource，必要扩展 | 真实 SSH/GPU 环境、驱动/数据/指标收集、恢复与停止验证需目标机器和授权；OR 仅满足上述门槛后采用 |
| 模型与费用 | 用底座既有成员模型配置，QA/实验分别有界 | 金额未知和 BYOK 限制必须明确。生产模型选择与开发订阅偏好分开 |
| 通知 | 主动相关通知和关联已获确认 | 频率、合并、用户静默偏好需验证/确认，不固定成全局产品决定 |

实施后的最终容量验证应覆盖约 20 名成员的实际使用组合并记录目标机配置；当前云端 4 CPU/16 GiB、历史目标 32 核/64 GB 或 54 核/192 GB 和“可能几百 GB 内存”的设想不互相替代。真实组织登录、模型和 GPU 验收需届时提供实际环境与权限；这些是未来验收依赖，不阻塞当前文档规划。
