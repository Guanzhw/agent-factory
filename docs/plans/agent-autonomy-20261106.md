# 自主 Agent 与统一工作入口

2026-11-06 用户明确调整方向：底座首先提供可用能力，删除妨碍工具使用和 Agent 自主工作的多余限制；研究不再采用代码强制的固定流程。可复用的实践应作为 Agent 可选择的工具、技能或其他能力。产品只保留一个用户入口。

这项决定取代此前研究控制器的固定轮次顺序与“项目工作台／个人研究会话”并列入口，不改变个人凭据和用户数据的归属。原始 v0.3 的平台优先、只补真实缺口原则，以及后续长期个人助手、临时实验 Agent、团队可读研究记录的目标继续适用。

现状说明：本计划原有的显式、持久及共享预算执行条款已由[当前 Runtime](../RUNTIME_DESIGN.md)取代。预算执行层已经移除，不再作为实现或验收要求，也不应据此恢复限制；自主研究与单一入口的产品方向不变。

## 实施边界

- 复用现有 ResearchSessions → Factory 原生 Agno Agent；不增加第三种执行引擎或通用多内核框架。
- Agent 根据目标与实际结果决定是否实验、是否委托、工具顺序和继续方向。项目、证据、实验和结论是可调用的数据能力，不是强制经过的阶段。
- 默认产品构建和启动采用同一应用组合；独立 Core 包继续不依赖研究业务，Core 的程序化装配能力不等于第二个产品入口。
- 普通界面突出目标、结果、需要决定的问题和失败；工具回执及子任务等细节可展开。停止、纠正和不确定回执仍然可见。
- 去掉委托运行时隐藏的深度 2／子任务 4 限制及重复的原生单次工具调用限制。不把提高常量当作最终解决所有限制。
- 保留真实用户文件、数据库记录、凭据、原任务标识及历史证据。删除旧新建入口不意味着清空数据库或重放旧任务。

## 保留边界及理由

个人资源归属和凭据不向团队泄露，是约 20 人共享使用的必要条件。原操作回执及确认停止用于避免重复执行和残留进程。尊重用户明确的任务约束和真实服务容量，不另设预算层或逐步审批。工具输入有效性检查保留在实际负责执行的边界，不重复铺设内部权限检查。

原生 Workflow 仍可被其他应用按需使用；研究业务不再要求所有任务经过某个固定 Workflow。尚未验证的 Loop、Team、并行工具及远端 GPU，不因本次删除限制而宣称已经可用。

## 验证

必须证明自主路径可直接回答、可选择实验或委托，历史可读，普通失败能准确呈现，未知回执不重复执行，停止确实作用于原任务。以超过旧隐藏委托上限的实际任务检查自主能力。界面检查单一入口、纠正／停止、资源返回与原操作恢复。

真实模型调用使用用户已授权的 OpenCode 订阅；不能将模拟测试当作真实模型或完整产品链路证据。PostgreSQL 二进制准备与本次重构并行，部署、系统服务及持久凭据另行处理。

参考 DeepSeek 官方 Super Agent 原型的单一用户体验与后台协作思路，不照搬其角色限制或新增框架：[理念](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/000-philosophy.md)、[领域模型](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/001-domain.md)。原型不是本项目运行能力的证明。
