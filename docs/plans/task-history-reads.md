# 规划：任务历史分页与读取、执行收尾分离

状态：Draft 实现与本地验收进行中，见 [执行记录](../../openspec/changes/paginate-task-history-and-separate-observation/verification.md)。基于可信团队重构 PR #95 的合并提交 `246f06541b21915392a77555e24f3f617d34de9f`。
建议 OpenSpec change：`paginate-task-history-and-separate-observation`。

## 问题与结果

成员应能找到较早任务，一个历史任务或目录接口异常也不应阻断整个工作区刷新。当前列表最多返回 100 个任务，并逐个读取完整执行详情；详情读取还可能触发取消和状态写入。此项交付可分页的轻量任务摘要、独立刷新，以及由执行观察者负责的收尾。

源码依据：

- `platform/agent_factory/store.py:319-320`：按创建时间查询，固定 `LIMIT 100`。
- `platform/agent_factory/factory_api.py:407-411`：`/jobs` 为每个任务调用 `detail`；`:176-212` 的详情路径可级联取消并写入 observed 状态。
- `web/App.tsx:126-155`：四个接口由一次 `Promise.all` 共同刷新，选中详情另行轮询；`web/TaskWorkspace.tsx:36-37` 没有更早历史入口。

以上为源码确认；当前规划没有测量用户实际历史规模或线上延迟。

## 实施范围

1. 为 `/jobs` 定义所有者范围内的 keyset 分页，稳定顺序为 `(createdAt, task id)`。公共 cursor 在输入边界验证一次，响应包含 items 与 next cursor。
2. 列表从已有持久化观察记录投影摘要，不逐项读取事件、产物和完整 native detail；明确摘要的观察时间。
3. 把 GET 路径中的执行状态变更归还给 observer 或显式 reconciliation。追踪科研与远程详情消费者，保证后台收尾在浏览器关闭时也继续工作。
4. 任务、目录和目标接口独立更新；错误在相应区域显示。增加“加载更早任务”，保持旧任务选中、返回和刷新行为。

## 验收

- [ ] 记录当前列表查询数、native 调用数、响应大小与耗时，作为同环境对照。
- [ ] 真实 PostgreSQL/HTTP 创建至少 205 个含相同时间戳的任务；完整翻页无遗漏或重复，其他成员无法使用 cursor 越权读取。
- [ ] 无任何列表/详情 GET 时，真实 native/observer 仍能完成本地和已支持远程任务的取消、失败收尾；GET 不产生生命周期写入或取消调用。
- [ ] 构建后的浏览器验证旧任务导航与键盘操作；一个目录接口失败时任务仍刷新。
- [ ] 比较同一数据集前后调用数与耗时，运行相关后端、Web 和 CI 检查。

保留所有者隔离、UNKNOWN 原身份和容量规则；过期摘要不能成为释放资源的依据。本项不引入全局缓存框架、搜索分析或新的执行队列。
