# 权限、运行限制与自主研究重构

基线：`9f70d56bbc8470f2b73a9ab0cd5dafa329fa8bdf`。依据用户 2026-11-06 的最新决定，优先提供可用能力，研究由 Agent 自主决定步骤；只有一个产品入口。参见[设计决定](../plans/agent-autonomy-20261106.md)。

## 已实施

| 原问题 | 修改及保留理由 |
| --- | --- |
| 固定 context/decide/launch/wait/results/evaluate/record 顺序 | 生产组合删除固定控制器，复用现有原生 Agent；旧实现移入测试夹具，不再随生产包发布。 |
| 项目工作台与研究会话各自新建工作 | 默认构建、启动与导航统一到自主任务入口；历史项目、证据和原任务链接只读保留。删除固定流程编辑与启动控件。 |
| 研究能力只能在固定 Workflow 步骤调用 | 项目读取、可选实验委托、直接命令实验记录、原结果查询、评估成为 Agent 工具；无需每项任务都做实验或委托。 |
| 隐藏深度 2／子任务 4 截断 | 运行时尊重显式声明的预算，支持原有 schema 范围 8／64；数据库约束同步扩展，不删除已有行。默认值仍为 2／4。 |
| 原生单轮工具上限与持久共享预算重复 | 删除原生 Agent 的第二道调用计数，保留原任务及祖先共享的持久计数。 |
| 会话最多 20 轮 | 删除固定上限；仍由用户选择正整数预算。 |
| 提示词一概禁止安装依赖 | 删除该额外禁令；Agent 按目标及用户边界选择已启用的命令能力。没有自动开启宿主命令或改变系统权限。 |
| 普通对话也必须先配置工作区、启用命令，并装齐全部工具 | 新会话只选择当前可用工具；无文件环境也可对话。底座允许真正无工具的模型应用，无需虚构工具或权限。模型预检、撤回检查保留，未启用命令仍不暴露。 |

实验记录包括可溯源回执和 Agent 评估，区分执行成功与科学结论。团队可读的整理结果不包含整个私人工作区、原始命令输出或凭据。已有用户数据没有删除或迁移。主 Agent 完成但子任务未停止时，不会发布完成结论；未知原回执通过原标识恢复，不启动替代操作。

## 审查中保留或尚未处理

- 保留资源归属、个人凭据隔离、撤回后的新操作检查、实际停止及原操作恢复：这是共享平台的业务正确性，不是逐轮审批。
- 保留显式预算和服务容量。当前 schema 的 8／64、工具调用 128、操作时长 600 秒等仍有上界；本次没有将它们宣称为 SDK 限制，也没有再提高任意常量。
- 原生 Workflow 的 Loop/Team/skills 等集成排除尚未解除；当前自主研究不依赖这些排除。未来应按实际消费者验证原生能力，而非默认再写框架。
- 普通工具错误是否都能作为观察继续、重复内部授权遍历以及 `parallel_tool_calls=False` 仍值得后续简化；不能未经并发和原回执验证直接删掉所有检查。
- 会话目标/边界 2,000 字符、上下文投影 12,000 字符与现有压缩机制仍保留，属于应用限制。
- 远端实验材料选择尚未与自主会话达到功能对等；GPU 分配仍未实现。不能用本地子 Agent 委托代替这些验收。
- 离线问答仍复用可选 QA 注册与身份服务；研究主路径不再依赖固定研究轮次，但 QA 身份耦合未在本次彻底拆除。

## 验证与独立复核

团队分别审查并实施底座、研究服务和 UI；另一位独立审查者检查完整改动。复审发现的“子任务仍运行却提前评估”和“直接记录中断后无法恢复”已修复，并增加回归。独立运行 22 项重点回归通过。

- 前端完整检查：58 个文件、674 项测试通过；lint、类型检查与生产构建通过。依赖审计零漏洞。
- Ruff、Pyright、Python 与前端依赖边界检查通过。
- PostgreSQL 17.11 隔离实例：委托深度/宽度、保留旧行的约束迁移及 17 项研究恢复验证共 19 项通过、零跳过。实例停止、PID 消失及临时数据/凭据清理均已确认。
- 完整 Python 初次回归发现 SQLite 测试夹具尚未识别新增 PostgreSQL 迁移 SQL；仅修正测试适配边界。另一个 SSH 假握手测试的同步竞争已用 20ms 延迟复现并修正，未改生产 SSH 代码。最终本地完整回归共 2,626 项，1,594 项通过，1,032 项按平台或 PostgreSQL 条件跳过，零失败／错误。
- 可选工具补充检查：隔离 PostgreSQL 会话、便携装配和无工具原生 Agent 共 26 项通过。完整 PostgreSQL CI 在提交 `42389286` 发现待启动任务 `run_id=None` 的观察错误及旧子任务预算断言；已修复，实际 Windows PostgreSQL 上两项回归均通过，并纳入 daily PostgreSQL 必跑选择。该次完整 CI 历史结果仍为失败；最终提交的 CI 状态以 PR 为准，不能把定向通过写成完整 PostgreSQL 全量通过。
- 用户授权的 OpenCode `opencode-go/deepseek-v4.1-flash` 完成一次真实只读设计复核，没有执行模型工具或改文件。它不等于产品内真实模型、浏览器登录或完整研究链路验收。

后续完整检查还暴露两项测试问题：Windows 句柄数值可被另一事件复用，不能以 `SetEvent` 成功判断继承；现以父事件信号为准，并加入真实继承和数值复用对照。子 Agent 取消测试曾传入 Python 绝对路径而非工具契约要求的命令名，命令未启动；修正夹具并将该取消用例纳入快速 PostgreSQL 必跑组。历史失败不计作通过，最终提交的完整矩阵结果以 PR 所链接运行及原始摘要为准。

取消夹具修复后，原生 Windows 隔离 PostgreSQL 的 `ResearchSubagentProbe` 整类 8 项通过、零跳过；停止前确认两个原进程句柄仍运行，停止后确认同一句柄退出。独立复核通过，临时数据库和凭据已清理。
