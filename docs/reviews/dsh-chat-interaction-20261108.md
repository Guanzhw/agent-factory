# DSH 聊天交互验收

2026-11-08，从 `main@f36be3d` 开始，使用独立工作树、端口、PostgreSQL 数据库和验收账号。原服务、数据库、未提交工作和会话没有被替换。

## 对照来源

实际查看本机 DSH Web 0.2.2-rc.1 的对话、整轮折叠、步骤展开和模型菜单。安装包中的 `dsh-client-ui-chat`、`dsh-client-ui-model-selection` 与 `dsh-client-ui-trajectory` 提供了实现依据。

`updateChunk` 按块更新内容，`TurnProcessNodeView` 展示整轮过程，`ModelSelect` 使用宿主提供的模型能力。`AssistantMarkdown` 的 `groupPart` 将同一次模型响应的思考与累积正文分开。Factory 沿用这种分组：响应之间的思考、阶段消息和工具保持顺序，同一最终响应的正文持续累积并独立显示。

截图和真实运行记录保存在仓库外，未提交安装包、凭据、完整对话或生成文件。

## 行为变化

- 普通聊天直接显示消息与正文。没有工具或思考时，不显示过程步骤。实际返回的思考单独流式显示并可折叠。
- 过程提供整轮、步骤摘要、单段思考或工具三层展开。最终回答在过程之外。相同调用的状态更新保留原记录和展开状态。
- 内部生命周期与正文片段进入独立诊断，不计入用户步骤。失败、停止、未知结果继续分别显示。
- 聊天内选择已配置模型与已核实的强度。下一轮固定选择，旧轮次与运行中的请求保留原配置。未知模型只显示提供方默认。
- 会话文件可直接预览 UTF-8 文本，并沿用原下载端点。切换会话、刷新文件或迟到响应不会串入旧预览。

## 运行时改动

Agno 继续负责模型与工具循环、队列、取消和原生历史。Factory 保留任务与原请求的关联，用于停止和恢复。正文与思考按响应和相邻段聚合，每 200ms、类型切换及结束时保存，不再逐 token 插入事件。

运行中的会话直接读取事件与工具结果，状态不变时不重复写会话行。终态保留快照。最终回答取原生完成消息，而不是包含工具前阶段消息的 `run.content` 总和。旧终态快照中曾经裁剪的片段不会自动补回。

独立 review 发现并修复两处后端问题：摘要辅助模型仍保留思考回调；取消发生在持久化等待期间时，最后一段可能被重复保存。前端 review 发现同一响应内思考与正文交替会使正文回退，现已按响应累积。

真实 Windows 验收还复现了 240 字符工作区中命令输出目录超过 MAX_PATH 的错误。内部文件边界改用 extended-length 路径，API 仍返回相对路径。输出准备失败明确表示未启动进程。目录重解析点拒绝和祖先目录保护保持有效。

## 真实模型和页面

现有订阅的 DeepSeek V4.1 Flash 完成普通问候，实际返回一段思考和正文。实页显示阶段消息、思考流、工具状态、三层折叠、文件预览和长回答。请求元数据确认 `high` 和 `low` 被实际序列化为 `reasoning_effort`。

切换至同订阅的 GPT-6 Luna/low 时，实际 Responses 请求携带所选模型和 `reasoning.effort`，提供方返回 HTTP 403。页面显示真实失败；这不算该模型的成功验收。

路径修复后，新的真实模型任务通过 API 完成退出 0 和预期退出 7 的命令，保存真实 stdout/stderr。随后另一个模型任务启动长命令，原生 Stop API 使已观察到的 Windows PID 退出。三次读取恢复没有新增模型调用，之前四轮记录逐项保持不变，旧未知操作没有被重放。

停止验收脚本最初用普通 Win32 路径读取 PID 文件，同样遇到 MAX_PATH。改用 extended-length 路径后，接管该次原调用完成停止和核对，没有重新执行命令。

文件下载 API 与原文件字节一致。Edge 收到了完整的 2,240 字节，下载卡片仍需保存确认。下载工具等待完成事件超时后，Computer Use 因无法可靠识别当前浏览器 URL 停止；最终路径补丁后的实页 Stop 未再操作。脚本浏览器独立覆盖按钮到真实进程停止的完整链路。
