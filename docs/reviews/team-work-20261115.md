# Team work records on 2026-11-15

Members can open **团队协作** from an existing chat and create a shared goal. The initiating member is the lead. Members publish selected contributions or request a configured colleague assistant's answer. The lead publishes a synthesis with references. Record entries retain their authors, original question, recipient, delivery, evidence and source identifiers.

The record stores only submitted content. Manual contributions link their selected private session. Agent contributions also retain the actual turn, task and run. A member can navigate to their own source session; shared evidence opens through the existing actor-aware source API. Personal histories, credentials and workspaces remain with their owners.

Contribution requests reserve the original private assistant message and a delivery-only private event in the same database transaction. The existing event worker recovers that message after a lost dispatch. Recipient execution uses its existing configured model and native Agno queue. Manual UI requests use delivery-only events and remain on the shared record. Native `research_request_contribution` reuses the existing collaboration intent and origin task. Its actual peer reply is adopted into the lead chat and continues that chat automatically, so the lead can call `research_synthesize_team_work` without another user turn. The record projects the actual answer and its current source availability.

Five optional chat tools expose shared records: `research_team_work`, `research_create_team_work`, `research_request_contribution`, `research_contribute`, and `research_synthesize_team_work`. Native reads register returned assistant-answer sources with the existing session source tracking. The lead check belongs to the synthesis write. Original request keys deduplicate writes and recovery.
