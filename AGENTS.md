# Project instructions

The selected platform is Agno AgentOS + PostgreSQL, targeting Agno 3.1.0. Reuse native Registry, components, authorization and lifecycle. Prefer a registered plan-aware executor with persisted immutable plans over a queue fork; its native durability and trust boundaries must be tested. Existing TypeScript/legacy SDK scaffolding is not the selected engine.

Product spine: versioned reusable materials (skills/tools/prompts/knowledge/models/environments), callable and manager-visible factory composition, then scoped core execution. Credentials are trusted user/task bindings, never catalog materials. Factory operations include discovery, plan/preflight, instantiate, inspect/reclaim, idempotency and permission recheck.

Prefer adopting or extending an existing complete platform and implement verified gaps. Eleven complete original design documents were reviewed privately; keep later scope deltas separate. Auto-Research is the first application. FR16 natural-language assembly is approved for current delivery: bounded approved-material selection, proposal, dependency/permission preflight and scoped temporary task instances. Shared-definition publication requires separate administrator review; temporary-plan approval policy remains undecided. Models cannot enlarge permissions or self-publish. Preserve parent delegation, shared budgets, depth/count limits and reclaim semantics. Do not invent private company workflow implementations.

Commit only new safe code, public docs and synthetic fixtures. Do not copy private design packages, credentials, personal files or company data into this public repository. Preserve third-party licenses and notices. Paid models/compute, deployment exposure and new access require explicit authorization. Open PRs as drafts; do not merge automatically.

Run `npm run check` and dependency audit for relevant changes. Verify actual runtime/browser behavior when it is available. Label model/ORX integration as unverified until it has run successfully; a client import or synthetic test does not prove live compatibility. Keep the acceptance matrix honest and distinguish planned from implemented features.

Remote runtime attachment and remote compute are foundational. Implement one selected-runtime adapter first; separate create/attach from environment allocation, reconcile unknown acknowledgements, retain scoped cancellation and artifact provenance. Single-server target profiles are 32 cores/64 GB and 54 cores/192 GB; no cluster or permanent heavy instance per user. Record actual host measurements separately from capacity targets.
